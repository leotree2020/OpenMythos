# G2-DESIGN-001 cross-review — original findings F1–F9 (preserved verbatim in substance)

Source: independent read-only design review of commit `8f9e8b2c027b3f6c0b738650b57af62d52dce141` (Claude Code reviewer), result **CHANGES REQUIRED**. File:line references are to `research/mini_mythos/a_predicate_003/bench/*` at repository HEAD `450914367c247231c51be02e13775cb001e69c5d` (identical `bench/` in `8f9e8b2`; zero diff). **F1 (high) — the reported pid is not bound to the ticket or the gate.** `observer.py:276-301` (`_on_created`), `103-126` (`_register`), `node.py::request_spawn`. `_on_created` takes the creator-supplied `pid = int(msg["pid"])`; `_register` only checks a stable starttime and `ppid == creator.pid`. Nothing checks that the pid holds the gate read end or that it is not already registered. Minimal counterexample (derived from source, not run): a released creator plain-forks a child Q, obtains TICKET_OK, `fork_gated`s the real child G and reports `CREATED pid=Q`; the observer registers Q, writes `R` to the gate whose only reader is G, so G runs unregistered while Q is the ledger identity; a later `kill_registered` (`observer.py:338-350`) or janitor (`janitor.py:44-72`) would SIGKILL Q. `trial.py:198` uses `gate_ino` only for write-end leakage. D03 omitted same-parent wrong child and duplicate pid. Suggested: add both fixtures; mandate (1) pre-release check that `/proc/<pid>/fd` contains `pipe:[gate_ino]` (unreadable -> BLOCKED), (2) node self-reported `READY.fp.pid` equals the registered pid, (3) global (pid, starttime) uniqueness. *(Revision note: item (2) was mis-stated as a pre-release check; READY is sent after release, so V1 reclassifies it as a mandatory detective check only. The original wording is kept.)*

**F2 (high) — G2-R01: under current code nobody lawfully waits for descendants.** `node_main` never waits and `exit_after_ready` is `os._exit(0)`; `Observer.reap_direct` (`observer.py:377-394`) covers only direct children; `sup_stub.bench_reap` (`sup_stub.py:69-82`, `115-116`) reaps only stub-created helpers named by a recipe `reap` op; only `candidates.py` / `sup_stub.py` touch `prctl`, and `truth.py:64` requires subreaper unset, so the observer is not a subreaper. A creator that never waits leaves the descendant zombie; after creator exit the descendant is adopted by PID 1, where the observer cannot `waitpid` and `/proc` disappearance is not attributable. Frozen Bench forbids changing `node_main`, and `request_spawn` hard-codes it. An "independent lawful reaper" can only be the real parent or an ancestor subreaper (a third process gets ECHILD). Suggested options: **A** a G2-specific creator entry (passed through `spawn_direct(entry=...)`) that waits by specific pid on an observer GO_REAP message and reports the raw status, with the observer independently observing pidfd-readable, `/proc` state Z with `ppid == creator`, and `/proc` gone only after GO_REAP; **B** observer as subreaper (changes the kernel behavior E1-A tests; not recommended by the reviewer). Orphan-to-init cases are "disappeared, reaper not attributable", never a lawful reap; E1A-d / E1A-e deliberately create orphans and must be excluded. Also `reap_direct` records `ECHILD` as `exit_status="ECHILD"` (`observer.py:386-388`) and `_confirmed_dead` treats any non-None status as dead (line 407), contradicting design §3.

**F3 (high) — ledger `DEAD` and `cleanup_confirmed` are satisfiable by unreaped zombies.** `common.process_is_dead` (`common.py:238-241`) counts Z as dead; used by `_confirmed_dead` (`observer.py:403`), `mark_dead` writes `DEAD` with basis "confirmed dead from /proc" (`observer.py:440-441`), `registry.lifecycle_issues` accepts `cleanup_confirmed=True` when every node has a `DEAD` (`registry.py:121-126`), `janitor.registered_still_alive` (`janitor.py:114`) likewise. V0 only noted this in the `common.py` row. G2 criteria must state that `DEAD` / `cleanup_ok` are not reap or residue evidence (G1 avoided this by collecting reap evidence independently).

**F4 (medium) — sender identity is socket possession, not process identity.** `proto.py` has no `SO_PASSCRED` / `SCM_CREDENTIALS`; `observer._handle` (`201-229`), `_on_ticket`, `_on_created` map socket -> node. A plain-forked descendant that inherits the creator's control socket can send TICKET / CREATED or steal TICKET_OK (gate_r + ctrl). `SO_PEERCRED` is useless on an observer-created socketpair (it returns the observer's credentials); per-message `SCM_CREDENTIALS` would be needed but Bench is frozen. Suggested: treat every node message as a claim cross-checked against `/proc`; add a "shared control fd bystander" case to D06.

**F5 (medium) — ledger has no lineage consistency checks and cannot hold the events of V0 §6.** `registry.py:9` KINDS lacks CREATED / EXIT / REAPED; a ticketed node's FORKED is written at receipt with a creator-asserted pid (`observer.py:88-100`, `290-300`); on late or aborted paths `forked_starttime` is read from whatever process now holds the pid (`observer.py:94-98`); `integrity_issues` / `check_order` (`registry.py:61-80`, `218-247`) do not check `REGISTERED.ppid == creator's REGISTERED.pid`, `INTENT.creator_pid`, or pid uniqueness. `RELEASED` is intent, written before the byte (`observer.py:131-133`); `release()` is outside the try in `_register` (`observer.py:124-126`), so `BrokenPipeError` escapes `_on_created` (tiny race window) leaving RELEASED durable without delivery; `FIRST_ACTION` is the delivery witness. Suggested: G2 sidecar evidence stream (G2 code, not Bench) for CREATED / EXIT / REAPED with timestamps; label ledger FORKED.pid "creator-asserted, unverified"; add the consistency checks.

**F6 (medium) — "complete `/proc` enumeration" is not a point-in-time snapshot.** `common.scan_proc` (`common.py:110-129`) records only unreadable entries; an entry that vanishes after `listdir` or a pid created after it is silent; `children_of` (line 132) ignores `problems`. A fork-and-exit unregistered process can evade; no single scan proves "no descendants" or "no residue". Suggested: >=2 scans with stable pid set and unchanged `ppid`, optional `/proc/sys/kernel/ns_last_pid` delta as a coarse bound, add `boot_id` and pidns inode to identity, starttime resolution is 1/CLK_TCK, `hidepid` unreadable -> BLOCKED (`truth.py:9-15`). *(Revision note: the "two stable scans" suggestion is withdrawn as a sufficiency claim in V1; see the revision record.)*

**F7 (medium) — system under test and independent witness undefined.** V0 §3 speaks of "the tested identity classifier" and "the candidate decision" but the source has only `Observer._register`'s ppid check, `cleanup_targets` and truth functions; `candidates.py` P0–P2 are R3 predicate candidates excluded by V0. With frozen Bench, prevention cannot be fixed in G2, only post-hoc detection; each card must state the SUT and whether the expectation is "observer refuses" or "G2 judge detects". D03's CPU fixture against the current `_register` expects "accepts wrong identity" (known defect, not PASS). Witness suggestion: a read-only sampler using only `common.read_stat`, writing a separate evidence stream, importing nothing from `registry` / `observer` classification; same-process independence is code-path only and must be stated.

**F8 (medium) — zero-signal is asserted, not enforced; no signal-free termination path.** `finish_cleanup` (`observer.py:456-486`), `final_cleanup` (`526-533`), `e1a_runner.py:319` (unconditional `final_cleanup` in `finally`), `trial._cleanup` (`trial.py:241-247`), autonomous janitor (`janitor.py:224-245`). Bench has no API to end live nodes without a signal; the observer never sends `EXIT` (only `FINISH` to the stub, `trial.py:247`); `node_main` exits on `EXIT` / EOF or after `T_NODE_MAX = 120 s`. Suggested: signal-free termination = close the control socket (EOF) plus budget; a G1Guard-like runtime guard trapping `kill_*`, `finish_cleanup`, `final_cleanup`, `PidfdHandle.send`, janitor start; guard is a Python-level trap, not kernel proof; kernel-side corroboration through non-signal wait status of every process (descendant status only creator-reported); MANUAL_DISPOSITION flow as in G1.

**F9 (low) — process budget contradictory; acceptance structure weak.** "No concurrent children" conflicts with parent + descendant alive together (ticket requires a RELEASED creator): define depth, total forks, max live, and timers `T_GATE_MAX = 10 s`, `T_REG_MAX = 5 s`, `T_NODE_MAX = 120 s`, total budget. DAC-01…07 are meta-conditions without run-level verdict precedence (suggest FAIL > BLOCKED > PASS) or check list; D04 / D07 "FAIL/BLOCKED per evidence" overlap (FAIL only on positive evidence of violation, missing / undecidable evidence is BLOCKED). D02: `REGISTERED.sid/pgrp` is captured before release (`observer.py:118`) and legitimately changes after `setsid`; judge must be time-indexed and read `/proc` after READY. Each card must say CPU-fixture-only vs REAL and which authorization it needs.

**Answers to the six focus questions (summary):** (1) concepts separated, but creator-claimed pid / ledger `creator_pid` / current `ppid` not distinguished; the pre-release `ppid` read while the child is still gated is the only independent kernel parent evidence. (2) V0 rows mostly accurate; omitted: no descendant reaping, Z-as-dead in the ledger, no CREATED / EXIT in ledger, socket identity != process identity. (3) G2-R01: nobody waits. (4) false-PASS routes: same-ppid wrong child, zombie taken as reaped, one-scan "no descendants", membership defined by sid/pgrp/ppid closure; late CREATED itself is fail-closed in source (`observer.py:282-294`). (5) unauthorized SIGKILL risk is real (F1 + F8). (6) acceptance insufficient (F7, F9).

**Minimal CPU-only discriminating experiments proposed by the review (not run):** forged ledger fixtures (same-ppid wrong child, duplicate pid, missing read-end binding) must give FAIL/BLOCKED never PASS; "Z not waited but ledger DEAD" must not give reap success; "pid appears/disappears between two scans" must give BLOCKED.
