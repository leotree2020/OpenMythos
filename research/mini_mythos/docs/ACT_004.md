# ACT-004 — Compute-Aware Depth Sweep (Phase 1)

**状态：** 代码已提交；需要在 Codespaces CPU 上实际运行。此阶段不修改上游模型源码。

## 研究问题

ACT-003 的扩大 Heldout 对照表明 Original ACT 在小型合成任务中平均 Loss 较低，但尚未建立计算成本和质量之间的关系。ACT-004 Phase 1 扫描最大循环深度 1、2、4，并记录每组 Loss 差异、ACT hook 捕获的循环调用次数、质量缺口比例和整组实验耗时。

**重要：** 当前实现中的 `len(observed)` 是全局执行的 recurrent block 次数，不是 token 级的有效 FLOPs；即使 token 提前停止，也不一定节约整个 recurrent block 的算力。整组 wall time 同时包含初始化、两条训练臂、梯度统计和 Heldout 评估，**不可当作单条 ACT 策略的延迟或速度提升**。本阶段只做探索性成本分析，不声称计算量匹配。

## 运行

在 Codespaces 的研究分支根目录：

```bash
git pull --ff-only origin mini-mythos-research
python -m unittest discover -s research/mini_mythos/tests -p 'test_*.py' -v

python research/mini_mythos/scripts/act_compute_sweep.py \
  --repo . --seeds 11 22 33 \
  --attentions gqa mla --depths 1 2 4 \
  --steps 30 --heldout-batches 30
```

输出：`research/mini_mythos/results/act004/sweep.json`，并在终端显示各配置的 Mean ΔLoss、Paired Wall Seconds、Original/Forced Forward Loop Calls、Original ACT Deficit Fraction。正的 ΔLoss = Forced Final Loss − Original ACT Loss，表示原版 Loss 更低。

建议先做快速验证：

```bash
python research/mini_mythos/scripts/act_compute_sweep.py \
  --repo . --seeds 22 --attentions gqa --depths 1 2 \
  --steps 3 --heldout-batches 5 \
  --out research/mini_mythos/results/act004/smoke.json
```

## 验收标准

1. 所有单元测试通过，所有 18 组实验产生有限的 Loss 和耗时。
2. 验证深度和循环次数对应关系；分析不同种子首次质量缺口的差异。
3. 不用 Paired Wall Seconds 推断 Original 和 Forced 两条训练臂的相对速度。
4. 后续 Phase 2 需要独立计时两条臂的前向/反向、控制测量顺序和预热，才可开始讨论实测延迟；若要比较 FLOPs，需另外进行可靠的算子级核算。
5. 当前使用的合成数据不能代表预训练模型的真实质量。
