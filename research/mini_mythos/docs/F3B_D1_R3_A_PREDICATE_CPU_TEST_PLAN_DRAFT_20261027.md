## 2. 共同的环境、独立观察与安全规则

- **环境：**仅 Linux CPU、标准库、不联网、不用 GPU、不用真实数据；记录内核、Python、Git 分支与提交、容器 / 虚拟化线索、`/proc`、`waitid`、`WNOWAIT`、`prctl(PR_SET_CHILD_SUBREAPER)` 是否可用、相关 pid / pgid / ppid / sid。
- **独立真实状态的来源（**不得使用待测的 A 本身**）：**测试台自己创建全部进程，因此**已知拓扑**（谁是谁的父进程、各自 pid，经管道回传）；每个进程的真实状态由两个独立手段交叉确认：`/proc/<pid>/stat` 状态字段（`R/S` 运行、`Z` 僵尸、消失 = 已回收），以及对直接子进程的 `waitid(WNOWAIT)`。两者不一致 → 该用例 `BLOCKED`。
- **安全：**只创建本测试专用的子进程与独立会话；只能向**已登记、指纹验证通过**的 pid 发信号；回收也只针对登记 pid；不得触碰终端、编辑器、Codespaces、其他用户或系统服务的进程；每个用例有短超时、`finally` 清理、结束后的残留检查（`/proc` 按令牌扫描 + `ps`）；身份不能确认就不发信号并报告 `BLOCKED`。
- **缩放计时：**宽限 / 轮询可缩放（仅验证逻辑，**不是**已批准 `G_term` 的实测）。
- **重复：**每个用例每个臂重复 N 次（建议 N=5，竞态用例 N≥50），要求结果一致；不一致记为 `FAIL`（不稳定）。
- **证据：**每个用例输出 JSON（环境、输入、拓扑、每次轮询的真实状态与 A、信号的 `result`/`errno`、`exit_record`、残留检查），并记录 SHA-256。

### 3.1 新增用例的完整规格（RV-02 / RV-03）

通用环境见第 2 节。下列每个用例的**实际状态均为 `NOT TESTED`**；表中的 PASS / FAIL / BLOCKED 是**未来执行时**的判据。三态与归属规则见提案 3.1、3.2；信号与 pidfd 见提案 3.3。

**T-12a — 应归属：跨会话后代，谱系链完整（RV-02）**
- 环境：子收割者开启；阶段根 R（`start_new_session`）→ 子 C → 孙 D；D 调用 `setsid()`，因此 `sid`、`pgrp` 都不等于阶段值；R、C 仍存活。
- 输入：D 忽略 SIGTERM 持续运行；轮询周期内扫描 `/proc`。
- 预期：D 因 `ppid` 链追到 R 而被归属为目标（`ALIVE`）；A 真；宽限点后升级，SIGKILL 只发给指纹验证通过的 D 等存活目标。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = D 被登记并终止，随后三态 `EXITED`；FAIL = D 被漏掉导致 `EXITED`，或 D 被当作「不属于本阶段」；BLOCKED = `setsid` / `/proc` 不可用。

**T-12b — 应归属：已登记后代在父进程死亡后被重新挂靠（RV-02）**
- 环境：同上，但 C 在 D 被登记（至少一次轮询）之后退出；D 已 `setsid()`，被重新挂靠到监督器（子收割者开启）。
- 输入：D 持续运行。
- 预期：因连续登记（L2），D 不因 `ppid` / `sid` / `pgrp` 的变化失去目标身份，A 真。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = D 仍是目标，`ALIVE` 并被终止回收；FAIL = D 丢失；记录真实 `ppid`，不假定为监督器。

**T-13a — 不应归属：世系之外的无关进程（RV-02）**
- 环境：测试台另起一个与阶段无关的进程 X（不同会话；`ppid` 不是监督器，也追不到阶段根）；其 `sid` 可以是任意值，包括刻意设为与阶段相同的编号（若无法构造则只做「不同」）。
- 输入：阶段子树全部退出，X 持续运行。
- 预期：X 不是目标，不使 A 为真，**不被发信号**；总体 `EXITED`。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = X 未被信号且结论 `EXITED`；FAIL = X 被信号，或因 X 存在而一直 `ALIVE` / BLOCKED。

**T-13b — 无法归属 → `UNKNOWN`/BLOCKED，不猜测（RV-02）**
- 环境：子收割者开启；监督器同时有一棵登记的辅助子树 H（不是本阶段）和阶段子树；两棵子树的后代在两次轮询之间都被孤立，监督器没有来得及登记，且两者都 `setsid()`。
- 输入：出现一个 `ppid`==监督器、未登记的孤儿 Y，来源无法判断。
- 预期：Y 为 `UNATTRIBUTABLE`，总体 `UNKNOWN`（`UNKNOWN_DISCOVERY_INCOMPLETE`），**不向 Y 发信号**，不判 `EXITED`。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = BLOCKED 且无信号；FAIL = 猜测归属并发信号，或判为 `EXITED`。

**T-14a — 指纹正确，目标在信号前退出（直接子进程）（RV-03）**
- 环境：目标是监督器未回收的直接子进程，指纹已验证；测试台在「指纹核对之后、发信号之前」注入钩子让目标自行退出。
- 输入：随后按流程发 SIGKILL（方案 A / B 各一次）。
- 预期：目标是僵尸；信号对僵尸无副作用；`sent` 的记录**不被解读为目标被该信号终止**；随后观察得到 `EXITED`；退出状态仍可取得且为自然退出的状态（不是 SIGKILL）。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = 无错误信号目标、退出状态如实；FAIL = 把 `sent` 记为被该信号终止，或退出状态被改写。

**T-14b — 指纹正确，目标在信号前退出（非直接子进程后代，被其父进程回收）（RV-03）**
- 环境：后代 G（C 的子）已指纹登记；测试台让 C 在「指纹核对之后、信号之前」回收 G。使用 pidfd 路径：先 `pidfd_open`，再核对指纹，再 `pidfd_send_signal`。
- 预期：`pidfd_send_signal` 返回 `ESRCH`，记录为 `gone`；不向任何其它进程发信号；pid 即使被立刻复用，信号也不会送到新进程。
- 实际状态：**NOT TESTED**（pidfd 在本环境的可用性 NOT VERIFIED）。
- 未来判据：PASS = `ESRCH`/`gone` 且复核无越界信号；FAIL = 信号送达他人；BLOCKED = `pidfd_open` / `pidfd_send_signal` 不可用（此时该目标 `UNKNOWN`，**不降级为裸 pid 发信号**，记录 BLOCKED 原因）。

**T-14c — 反例：裸 pid 路径在同一竞态下的风险（RV-03，仅对照）**
- 环境：同 T-14b，但使用「核对指纹后对裸 pid `os.kill`」的朴素实现，测试台用**测试专用的、可安全接收信号的诱饵进程**模拟「pid 被换成另一个进程」（以注入的守卫记录代替真实复用，不制造真实 pid 复用）。
- 预期：演示 TOCTOU 窗口确实存在（守卫日志中出现「信号目标与登记不符」的机会），证明指纹本身不能消除风险。
- 实际状态：**NOT TESTED**。
- 未来判据：此为演示用例；PASS = 对照臂（pidfd 路径）无越界；若对照臂也出现越界 → FAIL。

**T-15 — pidfd 的打开 / 核对顺序与整组信号的安全条件（RV-03）**
- 环境：(a) 组领头是监督器未回收的子进程，组内成员都已归属；(b) 领头已回收后组内仍有存活成员；(c) 组内有一个 `UNKNOWN` 成员。
- 输入：到宽限点需要升级。
- 预期：(a) 可用 `killpg`（满足提案 3.3 的三个条件）；(b) 禁用整组信号，改为逐目标 pidfd；(c) 禁用整组信号，仅向 `ALIVE` 且身份已验证的目标逐个发送，`UNKNOWN` 成员不被信号。另检：先 `pidfd_open` 再核对指纹的顺序（用注入让 pid 在两步之间被换成另一个进程 → 指纹不符，不发信号）。
- 实际状态：**NOT TESTED**。
- 未来判据：PASS = 三种情形的信号选择与预期一致且无越界；FAIL = (b) 或 (c) 使用了整组信号，或顺序反了；BLOCKED = pidfd 不可用。

**T-16 — 真实 pid 复用（RV-03）**
- 环境：需要写 `/proc/sys/kernel/ns_last_pid`（特权）或大量 fork 回绕。
- 实际状态：**NOT PLANNED / NOT TESTED**。理由：无特权环境不可靠，且制造真实 pid 复用有影响他人进程的风险。保留为已知的未覆盖风险，提案不得因此声称「已消除」。

**与 G1–G6 的关系（仅供规划）：**T-01/T-02/T-03/T-08 重跑并补强 G1/G2；T-02/T-08 部分触及 G3；T-04–T-07 触及 G5；T-09 触及 G4 之外的安全面；T-10、T-11a～e 是新增的误回收与不可证明用例；T-12～T-16 覆盖跨会话后代与信号竞态。**G3–G6 的 NOT TESTED 状态不因本计划改变。**

## 4. 验收标准（每个候选臂）

- **PASS：**全部用例的预期都满足；重复结果一致；**零次误回收、零次向未登记 / 指纹不符进程发信号**；残留检查为空；基线臂 B0 复现了已知 FAIL（否则测试台无效 → `BLOCKED`）。
- **FAIL：**任一用例不符预期、不稳定，或出现一次误回收 / 越界信号。
- **BLOCKED：**两个独立观察手段不一致、环境缺少必需能力（`/proc`、`waitid`、`WNOWAIT`、`prctl`、`pidfd`）、或身份无法确认。**作为被测对象的 `UNKNOWN`**（候选臂在 T-11、T-13b 等用例中应当给出 BLOCKED）与测试台自身的 BLOCKED 分开记录：前者是预期行为（用例 PASS），后者使用例无效。
- **UNKNOWN 纪律：**任何用例里，`UNKNOWN` 被转换为 `EXITED` / `confirmed`=true，或在 `UNKNOWN` 时发出新信号，均直接 FAIL。
- 工具运行的 PASS 与候选方案的规则 PASS **分开记录**（沿用 G1/G2 实验的做法）。
- **选择规则（若两臂都 PASS）：**由 ChatGPT 与 Grok 交叉审核、项目负责人裁决；起草者倾向不构成决定。

## 5. 不能确认的事项（明确列出）

- 其它内核 / 环境的差异（审核者在 6.18.55 上的观察需要在同一测试台里复现）。
- 真实 pid 回绕复用；cgroup 级别的进程归属（本计划不使用 cgroup）。
- 先 `setsid()` 后被 init 收养的逃逸后代：子收割者开启时可被看见（T-12）；未开启时完整性证据缺失，总体只能 `UNKNOWN`（T-04b-A、T-11d）。是否因此禁止整个运行属于维度 B（T-04b-B），待负责人裁决。
- 指纹核对与信号之间的 TOCTOU 窗口不可消除；pidfd 只改善单个进程（T-14、T-15）；真实 pid 复用 NOT PLANNED（T-16）。pidfd 在本环境的可用性 NOT VERIFIED。
- 完整监督器行为、与 `subprocess.Popen` 的交互（候选臂在测试台里自管子进程）。
