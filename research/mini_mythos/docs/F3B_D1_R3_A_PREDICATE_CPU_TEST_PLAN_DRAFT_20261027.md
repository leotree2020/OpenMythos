## 2. 共同的环境、独立观察与安全规则

- **环境：**仅 Linux CPU、标准库、不联网、不用 GPU、不用真实数据；记录内核、Python、Git 分支与提交、容器 / 虚拟化线索、`/proc`、`waitid`、`WNOWAIT`、`prctl(PR_SET_CHILD_SUBREAPER)` 是否可用、相关 pid / pgid / ppid / sid。
- **独立真实状态的来源（**不得使用待测的 A 本身**）：**测试台自己创建全部进程，因此**已知拓扑**（谁是谁的父进程、各自 pid，经管道回传）；每个进程的真实状态由两个独立手段交叉确认：`/proc/<pid>/stat` 状态字段（`R/S` 运行、`Z` 僵尸、消失 = 已回收），以及对直接子进程的 `waitid(WNOWAIT)`。两者不一致 → 该用例 `BLOCKED`。
- **安全：**只创建本测试专用的子进程与独立会话；只能向**已登记、指纹验证通过**的 pid 发信号；回收也只针对登记 pid；不得触碰终端、编辑器、Codespaces、其他用户或系统服务的进程；每个用例有短超时、`finally` 清理、结束后的残留检查（`/proc` 按令牌扫描 + `ps`）；身份不能确认就不发信号并报告 `BLOCKED`。
- **缩放计时：**宽限 / 轮询可缩放（仅验证逻辑，**不是**已批准 `G_term` 的实测）。
- **重复：**每个用例每个臂重复 N 次（建议 N=5，竞态用例 N≥50），要求结果一致；不一致记为 `FAIL`（不稳定）。
- **证据：**每个用例输出 JSON（环境、输入、拓扑、每次轮询的真实状态与 A、信号的 `result`/`errno`、`exit_record`、残留检查），并记录 SHA-256。

## 3. 用例

「预期 A」「预期升级 SIGKILL」是**按 RA-1…RA-10 的意图**写的，不是按任一方案的输出写的。升级 SIGKILL 的口径：在宽限点（或模拟的宽限点）若 A 为真则**应**升级；若 A 为假**不应**升级。

| ID | 目的与输入 | 独立真实状态 | 预期 A | 预期升级 SIGKILL（宽限点） | PASS / FAIL / BLOCKED 判据 | 残留与安全检查 |
|---|---|---|---|---|---|---|
| T-01 | 持续运行的直接子进程（忽略 SIGTERM）。**目的：**A 不遗漏真正的活进程 | 直接子进程 `R/S`，`waitid` 无变化 | 真 | **应升级**（到宽限点仍运行） | 三臂 A 均为真且升级 → PASS；任一臂 A 为假 → FAIL | 仅向该子进程发 SIGKILL，随后回收；残留为空 |
| T-02 | 直接子进程正常退出（`exit(7)`）且监督器暂不回收；另有被信号杀死的变体。**目的：**已退出未回收不使 A 为真，**且退出状态不丢** | `Z`，`waitid`=`EXITED`（码 7 / 被信号杀死） | 假 | **不应升级** | A 为假、不升级、**记录的退出状态与真实一致**（CA：`exit_record`；CB：T5 回收返回值与 `waitid`）→ PASS；A 为真或状态丢失 / 错误 → FAIL。基线预期 FAIL（复现 G1-02） | 回收后 `waitid`=`NOCHILD`；无残留 |
| T-03 | 进程组里**只有**已退出未回收的直接子进程。**目的：**A 不再依赖 `killpg(pgid,0)`；记录 `killpg0` 为参考 | 组成员仅一个 `Z` | 假 | **不应升级** | A 为假且不升级 → PASS；基线预期 FAIL（复现 G2-01）；`killpg0` 的返回值只记录，不判定 | 同上 |
| T-04 | 领头进程退出（僵尸）而其子进程仍在**同一进程组**运行（子收割者开启）。**目的：**僵尸领头 + 活跃后代 | 领头 `Z`，后代 `R/S`，后代 `ppid`=监督器（已重新挂靠） | 真 | **应升级**（若后代忽略 SIGTERM） | A 为真、升级只发给指纹验证通过的存活目标 → PASS；A 为假（遗漏后代）→ FAIL | 先终止后代再回收领头；无残留 |
| T-04b | 同 T-04，但子收割者**不可用**（模拟 `prctl` 失败）。**目的：**S0 预检行为 | 后代被 init 收养（`ppid`=1），会话号仍匹配 | — | — | 预检必须 `BLOCKED`（`PREFLIGHT_FAILED`），不进入运行；若仍声称能确认 → FAIL | 仅清理自己创建的后代 |
| T-05 | 一个存活的领头进程，其子进程之一已退出（僵尸，领头尚未回收它），另一个子进程运行。**目的：**活跃与僵尸后代并存；**僵尸属于一个活着的父进程，不是监督器该回收的** | 僵尸 `Z`（父 = 领头，存活）、活跃子进程 `S` | 真 | 应升级（若领头 / 子进程忽略 SIGTERM） | A 为真；监督器**不得**回收那个僵尸（它不是监督器的子进程）→ PASS；回收了或 `waitpid` 报错未处理 → FAIL | 无残留；该僵尸在领头退出后被重新挂靠、再由监督器按 pid 回收 |
| T-06 | 全部目标均已退出且为**重新挂靠的僵尸后代**（领头已死、后代已死）。**目的：**A 为假且 `confirmed` 前被回收 | 后代 `Z`，`ppid`=监督器 | 假（回收前后均假） | **不应升级** | A 假；按 pid 回收后 `residual` 为空、`confirmed`=true → PASS；僵尸遗留或 A 为真 → FAIL | `/proc` 无残留僵尸 |
| T-07 | 重新挂靠的**活跃**后代（领头已死，后代运行）。**目的：**RA-5 | 后代 `R/S`，`ppid`=监督器 | 真 | **应升级** | A 真且 SIGKILL 后变僵尸、被回收、`confirmed`=true → PASS | 后代被回收，无残留 |
| T-08 | **SIGTERM 到宽限期截止的竞态**：(a) 进程在截止点之前退出；(b) 在截止点处退出；(c) 在最后一次复核之后、发信号之前退出。**目的：**RA-6 | (a)(b) 僵尸；(c) 复核时运行、发信号时已退出 | (a)(b) 假；(c) 复核时真 | (a)(b) 不升级；(c) 允许发出 SIGKILL，结果必须是 `gone` / 对僵尸无副作用，**不得发给无关进程** | (a)(b) 无错误升级、(c) 的信号只发给指纹验证通过的目标 → PASS；N≥50 次中任一次错误升级 → FAIL | 无残留；信号日志只含登记 pid |
| T-09 | **PID/PGID 复用的防护**：向守卫注入「过期记录」（改写 `starttime` / 回收后再签发）。**目的：**RA-7 | 目标已被回收或指纹不符 | — | **不发信号** | 守卫拒绝（`SafetyError`），无任何信号发出 → PASS；发出信号 → FAIL。**真实的 pid 回绕复用难以在无特权环境可靠制造，标 NOT TESTED（仅测防护逻辑）** | 无信号发出 |
| T-10 | **不得误回收其他进程**：监督器持有一个与目标无关的「诱饵」子进程，它在轮询期间退出。**目的：**RA-8 | 诱饵 `Z`，由测试台自己回收 | — | — | 候选臂**不得**回收诱饵（诱饵直到测试台自己回收前保持 `Z`，`waitid`=`EXITED`）→ PASS；诱饵被回收 → FAIL。基线 T5 的 `waitpid(-1)` 变体预期 FAIL（演示风险） | 诱饵由测试台回收；无残留 |
| T-11 | **`/proc` 不可用 / 扫描出错**（用注入的读取失败模拟）。**目的：**RA-9 | — | **不得判为假** | 不升级也不确认 | 候选臂返回 `BLOCKED`（`TERMINATION_UNCONFIRMED`）→ PASS；返回 A 为假 → FAIL | 无信号 |

**与 G1–G6 的关系（仅供规划）：**T-01/T-02/T-03/T-08 重跑并补强 G1/G2；T-02/T-08 部分触及 G3；T-04–T-07 触及 G5；T-09 触及 G4 之外的安全面；T-10、T-11 是新增的误回收与不可证明用例。**G3–G6 的 NOT TESTED 状态不因本计划改变。**

## 4. 验收标准（每个候选臂）

- **PASS：**全部用例的预期都满足；重复结果一致；**零次误回收、零次向未登记 / 指纹不符进程发信号**；残留检查为空；基线臂 B0 复现了已知 FAIL（否则测试台无效 → `BLOCKED`）。
- **FAIL：**任一用例不符预期、不稳定，或出现一次误回收 / 越界信号。
- **BLOCKED：**两个独立观察手段不一致、环境缺少必需能力（`/proc`、`waitid`、`WNOWAIT`、`prctl`）、或身份无法确认。
- 工具运行的 PASS 与候选方案的规则 PASS **分开记录**（沿用 G1/G2 实验的做法）。
- **选择规则（若两臂都 PASS）：**由 ChatGPT 与 Grok 交叉审核、项目负责人裁决；起草者倾向不构成决定。

## 5. 不能确认的事项（明确列出）

- 其它内核 / 环境的差异（审核者在 6.18.55 上的观察需要在同一测试台里复现）。
- 真实 pid 回绕复用；cgroup 级别的进程归属（本计划不使用 cgroup）。
- 先 `setsid()` 后被 init 收养的逃逸后代（子收割者可用时可被看见；不可用则预检 BLOCKED）。
- 完整监督器行为、与 `subprocess.Popen` 的交互（候选臂在测试台里自管子进程）。

## 6. 分歧与最小裁决实验（当 ChatGPT 与 Grok 的意见不同）

| 可能的分歧点 | 最小裁决实验 |
|---|---|
| 方案 A 的「回收即消耗」是否会在竞态下丢失退出状态 | T-02、T-08 的高重复版（N≥1000），对比 `exit_record` 与真实退出状态 |
| 方案 B 的「僵尸滞留」是否带来实质风险（例如 T5 漏掉回收） | 在 T-06 / T-07 里人为跳过 T5，观察残留与 `confirmed` 的判定 |

| `/proc` 依赖是否可接受 | T-11 的多种注入失败（权限、竞争消失的 pid） |
| 子收割者前提是否过严 | T-04b 的预检行为与替代方案（仅会话号扫描）对比 |
