# F3B-D1-G1G2-CPU-001 — 实验报告：R3 存活目标判定 A 的 CPU 正确性（G1 / G2）

**授权：** OWNER AUTHORIZED（控制性 CPU 正确性实验）。**状态：实验已执行，工具运行 PASS；R3 存活判定规则 G1 = FAIL，G2 = FAIL（待 ChatGPT 独立审核）。**这不是 R3 规范的修改：冻结的 R3 与负责人决策记录字节不变；下面的修订只是**建议**，未应用。

## 1. 先于结果登记的判定准则

准则写在探针代码里（`EXPECTED_A`、三种读法 `PROCEDURES`、`consistent` 的定义），先于正式运行；**不以待验证的 A 本身作为正确性标准**。

- **独立真实状态**由两个互相独立的观察手段给出，必须一致，否则该用例 `BLOCKED`：非消耗式 `os.waitid(P_PID, pid, WEXITED|WNOHANG|WNOWAIT)` 与 `/proc/<pid>/stat` 的状态字段（`R`/`S` 运行，`Z` 僵尸，文件消失 = 已回收）。
- **规范意图（来自 R3 §11.1(d)）：**「A 为假」即「所有目标进程都已退出」。因此期望：`RUNNING → A 为真`；`EXITED_UNREAPED → A 为假`；`REAPED → A 为假`。冻结检查点的 G2 门禁还要求「进程已退出但尚未回收时，不得错误认定仍需 SIGKILL」。
- **A 的字面实现**（`r3_A`）：条件 (1) 直接子进程**尚未被 waitpid 回收**（监督器账目 `reaped` 标志）；条件 (2) `killpg(pgid, 0)` 成功；条件 (3) 存在被重新挂靠到本进程下的、不属于本探针登记子进程的后代（`/proc` 扫描）。三者任一为真则 A 为真。
- **R3 文字允许的三种读法**（R3 没有规定 A 的检查与 `waitpid(WNOHANG)` 的先后，§11.1(c)5 只说轮询里用 `waitpid(WNOHANG)`，T5 才写回收）：`NOREAP`（T3 内不调用 waitpid，只在 T5 回收）、`EVAL_THEN_REAP`（先算 A 再 `waitpid(WNOHANG)`）、`REAP_THEN_EVAL`（先 `waitpid(WNOHANG)` 再算 A）。
- **规则判定：**规则文字必须在它允许的**每一种**读法下都与规范意图一致；任一读法不一致 → 该用例规则 `FAIL`（并记录是哪种读法）。A 与独立真实状态不一致、或建议在子进程已退出时升级 SIGKILL，都按此判定；**不会为了让它通过而改 A**。
- **两个结果分开：**(A) 工具是否正确运行（`tool_status`）；(B) R3 规则是否满足 G1/G2（`rule_status`）。

**透明度：**正式运行之前，我为调试探针工具本身做过 3 次试运行（输出在会话临时目录，未入库）。它们暴露了探针的两个工具缺陷并已修复：① 子进程 `fork` 后、`exec` 前其 `cmdline` 还不含探针令牌，安全守卫正确地**拒绝**了向它发信号——改为 `spawn` 等到 `exec` 完成后才返回；② 正在退出的进程已释放内存映射，`cmdline` 读出为空，守卫改为允许「未回收的本探针子进程」的空 `cmdline`（pid 在回收前不可能被复用），非空但缺令牌仍拒绝，回收后不再允许发信号。判定准则在这些修复中没有改变。

## 4. 整体结果

| 维度 | 结果 |
|---|---|
| **A. 工具是否正确运行** | **PASS**：6 个用例 × 5 次重复，两个独立观察手段始终一致；每个信号都经过安全守卫；残留检查为空（见检查点）；9 个单元测试通过 |
| **B. G1（`waitpid(WNOHANG)` 与存活目标 A 的协调）** | **FAIL**：G1-02 在 R3 允许的 2 种读法下，A 对「已退出未回收」判为真 |
| **B. G2（已退出未回收不得错误认定需 SIGKILL）** | **FAIL**：G2-01 条件 (2) 对僵尸组仍成功；G2-02 在 `NOREAP`（自然与竞态）与 `EVAL_THEN_REAP`（竞态）下产生错误的 SIGKILL 升级建议 |

**不能因为脚本运行成功就宣布 G1/G2 PASS：**证据采集 PASS，但 R3 存活判定规则的架构正确性 FAIL。

## 5. 诊断（仅分析，不修改冻结 R3）

- 条件 (1)「直接子进程尚未被 waitpid 回收」是**账目事实**，不是「进程是否还在运行」：子进程一旦退出而父进程未回收，它保持僵尸，条件 (1) 持续为真。
- 条件 (2) `killpg(pgid,0)` 对**只含僵尸的进程组**仍返回成功（本环境 5/5），回收之后才变 `ESRCH`；`kill(pid,0)` 同理。因此条件 (2) 也不能区分「运行」与「已退出未回收」。
- 所以按字面（不在 A 之前回收）A 在已退出未回收时恒为真，宽限用尽时会**错误升级 SIGKILL**。把 `waitpid(WNOHANG)` 放在 A 的求值**之前**（`REAP_THEN_EVAL`）则全部用例都与意图一致；放在**之后**（`EVAL_THEN_REAP`）只在「子进程恰在两次轮询之间退出而下一次轮询就是宽限点」时出错。
- R3 文字（§11.1(c)5、T3、T5）没有规定这个顺序，因此是**规格缺陷（缺口 / 歧义）**，不是实现问题。

### 建议的修订方向（**未应用**；须 ChatGPT 独立复审并由项目负责人对行为变更裁决，且按冻结记录第 6 节走变更流程）

1. 规定 T3 每个轮询周期**先**对直接子进程做 `waitpid(WNOHANG)`（回收已退出者），**再**计算 A；条件 (1) 改述为「直接子进程尚未退出（未被观察到退出）」。
2. 或者保持不回收，但让 A 使用**非消耗式**观察：`waitid(P_PID, pid, WEXITED|WNOHANG|WNOWAIT)` 判定退出，`/proc` 状态 `Z` 的进程不计入存活。
3. 条件 (2) 对僵尸组不可靠：要么在回收之后才使用，要么以「组内存在非 `Z` 状态成员」替代。
4. 条件 (3)（被重新挂靠的后代）在重新挂靠的**僵尸后代**上有同样的问题，属于 G5 的范围，本实验未测。

## 6. 范围与未测事项

- 本实验只覆盖 G1、G2 的**直接子进程与同组子进程**；条件 (3)（`PR_SET_CHILD_SUBREAPER`、重新挂靠的后代）没有构造，G3–G6 **未启动，保持 NOT TESTED**。
- 缩放计时（0.5–1.0 s 宽限）只用于验证谓词的逻辑，**不是**已批准的 `G_term`=10 s 的实测，也不验证 1 s 轮询粒度。
- 结果来自一个内核 / 环境（Linux 6.18.44，microVM）；其它内核对僵尸组 `killpg(pgid,0)` 的行为需单独确认。
- 没有下载数据、拟合 Tokenizer、运行 D1、训练、使用 GPU 或启动 D2/D3；没有修改冻结文件、v1/R1/R2、Driver / Reader / Verifier、上游 Parcae 与模型代码。
