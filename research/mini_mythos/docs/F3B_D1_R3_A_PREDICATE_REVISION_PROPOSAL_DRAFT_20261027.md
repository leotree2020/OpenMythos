## 3. 两个候选方案的共同部分

下面几项对方案 A、方案 B **相同**，因此不是二者的差别：

- **目标集合与身份锚点（RV-02 修订）：** 每个阶段以 `start_new_session=True` 启动，其会话号 `sid` = 进程组号 = 直接子进程 pid。目标集合按**谱系**确定（3.2）：阶段根进程 + 由 `ppid` 链追到阶段根的全部后代 + 一经登记就持续跟踪的后代 + 按排除法归属的被重新挂靠孤儿。**会话号 / 进程组号只是正向发现提示，不是必要条件，也不能用来排除**（`setsid()` 会改变它们）。**不用 `killpg(pgid, 0)` 的返回值**判断存活（降为只记录的「参考观察」）。
- **指纹：** 在 spawn 时记录 `(pid, starttime, sid, pgrp)`（`starttime` 是 `/proc/<pid>/stat` 第 22 项，开机后的时钟节拍，同一次开机内与 pid 一起唯一标识一个进程）；之后任何信号或回收之前先核对指纹。目的：RA-7、RA-8。**限定：**指纹只证明「核对那一刻」这个 pid 对应的是登记过的进程，**不**证明信号送达那一刻仍是它（3.3）。
- **存活判定：** 目标 `/proc` 状态是 `Z`（僵尸）或 `X`（已死）→ 不计入存活；其余（`R`、`S`、`D`、`T` 等）→ 存活。
- **子收割者（RV-04 修订）：** 监督器在 S0 尝试设置 `PR_SET_CHILD_SUBREAPER` 并用 `PR_GET_CHILD_SUBREAPER` 读回。**两个维度分开评价（3.4）：** A. 系统调用与重新挂靠的实际行为（CPU 测试判断）；B. 设置失败时是否必须禁止整个运行（**实施策略，待负责人裁决**，默认安全退路建议 `BLOCKED`，但不是冻结 R3 的既定规则）。无论 B 如何裁决，**子收割者未被验证开启 ⇒ 发现范围完整性证据缺失 ⇒ 总体不得为 `EXITED`**（3.1）。
- **T5 的回收规则：** 删去 `waitpid(-1, WNOHANG)`；只对**已登记且指纹验证通过**的 pid 调用 `waitpid(pid, WNOHANG)`。
- **SIGKILL 前复核：** 发 SIGKILL 之前，立即重新计算一次三态；`EXITED` 则**取消升级**，`UNKNOWN` 则**不发信号**（RA-6、RA-9）。信号只发给**被证实为 `ALIVE` 且身份已验证**的目标；单进程用 pidfd 并按 3.3 的顺序；整组信号只在 3.3 的安全条件下使用，否则逐目标发送（RA-7）。
- **`/proc` 不可用或扫描出错 → 三态为 `UNKNOWN` → BLOCKED `TERMINATION_UNCONFIRMED`**，不得当作 `EXITED`，也不得据此发信号（RA-9，3.1）。

> 关于 PID/PGID 复用的内核事实（需受控测试验证，本草稿未验证）：只要还有任何进程以某编号作为进程组号或会话号，该编号就不会被分配给新进程；监督器**尚未回收**的子进程，其 pid 在回收前不可能被复用；叶进程被回收且组清空后编号才可能复用。所以「回收之后再对旧编号发信号」「对非子进程后代按裸 pid 发信号」才是危险点。

### 3.1 三态判定与组合规则（RV-01）

**每个目标的状态：**

| 状态 | 条件（需要独立证据） |
|---|---|
| `ALIVE` | 身份已按指纹验证，且当前观察显示未退出：直接子进程 `waitid(WNOWAIT)` 无变化（方案 A：`waitpid(WNOHANG)` 返回 0），或 `/proc` 状态不是 `Z`/`X` |
| `EXITED` | 有证据表明已退出：直接子进程 `waitid`=已退出，或已回收且状态已保存；`/proc` 状态 `Z`/`X`；或**此前已按指纹验证身份**的 pid 现在 `/proc` 不存在（`ENOENT`，进程已消失 / 已回收） |
| `UNKNOWN` | 身份无法验证（指纹缺失，或 pid 仍存在但指纹不符）；`/proc` 读取失败（`EACCES`、I/O 错误、解析失败）而无法证明已退出；`waitid` 与 `/proc` 观察自相矛盾；无法归属（3.2） |

**总体三态（目标集合 + 发现范围）：**
1. 任一目标 `ALIVE`（有证据）→ 总体 `ALIVE`（A 为真）。其它目标是 `UNKNOWN` 也不改变这一点，但信号**只发给 `ALIVE` 且身份已验证的目标**。
2. 否则，任一目标 `UNKNOWN`，**或发现范围的完整性证据缺失** → 总体 `UNKNOWN`（A 没有取值）。
3. 否则（全部目标 `EXITED` 且完整性证据成立）→ 总体 `EXITED`（A 为假）。

**发现范围的完整性证据（必须全部成立）：** (i) 子收割者已用 `PR_GET_CHILD_SUBREAPER` 读回确认开启；(ii) 本轮 `/proc` 枚举完整——每个数字目录要么成功读取 `stat`，要么有证据表明 pid 已消失（`ENOENT`），任何其它错误都算不完整；(iii) 每个 `ppid` 为监督器的进程都能按 3.2 归属（目标或登记的辅助进程），存在无法归属者即不完整；(iv) 结论为 `EXITED` 之前，目标集合在连续两次扫描之间不变。

**`UNKNOWN` 的处理：** 不得转换为 A 真 / 假的成功结论；**不得据此发送新信号**（包括升级 SIGKILL，也不向 `UNKNOWN` 目标发信号）；结果为 BLOCKED `TERMINATION_UNCONFIRMED`，`confirmed`=false、`t_gone_bt_ns`=`null`；原因码记在既有字段里（每个 `UNKNOWN` 目标一条 `reap_done.residual` 条目；`run_aborted.code`），原因码取自 `UNKNOWN_PROC_UNREADABLE` / `UNKNOWN_TARGET_UNREADABLE` / `UNKNOWN_IDENTITY_UNVERIFIED` / `UNKNOWN_DISCOVERY_INCOMPLETE` / `UNKNOWN_OBSERVATION_CONFLICT`。**不增加新事件。**

### 3.2 跨会话后代的归属（RV-02）

**问题：**后代调用 `setsid()` 后，它的 `sid`、`pgrp` 都不再等于阶段的值。若目标集合靠会话号定义，这样的后代会被漏掉，A 可能错误地成为 `EXITED`。

**归属规则（草案）：**

| 规则 | 内容 |
|---|---|
| L1 谱系闭包 | 从已指纹登记的阶段根进程出发，沿 `ppid` 取传递闭包；闭包内的进程是目标，**无论其 `sid` / `pgrp` 是否改变** |
| L2 连续登记 | 每个轮询周期把新发现的闭包成员（含指纹）加入登记表；一旦登记，就**不因** `ppid`、`sid`、`pgrp` 的变化（`setsid()`、被重新挂靠）而失去目标身份，直到被确认 `EXITED` |
| L3 封闭世界排除法 | 子收割者开启时，`ppid` 为监督器、未登记为目标、也不是登记的辅助进程的进程，必定是监督器某个子进程的子树被孤立后的后代。**若监督器在该阶段运行期间没有未登记的辅助子树**（监督器断言：阶段运行期间不创建其它子进程；任何辅助子进程必须先登记并指纹化，其后代同样按 L1 / L2 跟踪），则这样的孤儿只能来自阶段子树 → 归属为目标 |
| L4 不得用 sid 排除 | `sid` / `pgrp` 匹配只作正向发现提示；**不匹配不是「不是本阶段后代」的证据** |
| L5 世系之外 | 沿 `ppid` 追不到阶段根、也不是 `ppid`==监督器的进程（与阶段无关的兄弟进程、其他用户的进程等）→ **不是目标**：不使 A 为真，**不得发信号** |
| L6 无法归属 | 辅助子树与阶段子树同时存在，而某个孤儿在被观察到之前就已被孤立，无法判断来自哪一棵 → `UNATTRIBUTABLE` → 总体 `UNKNOWN`（`UNKNOWN_DISCOVERY_INCOMPLETE`），**不得猜测**，也不向它发信号 |

**可观察性的限度（明说）：**(a) 子收割者未开启时，被孤立的后代会被最近的其它子收割者祖先或 init 收养，监督器看不到它们——这是完整性证据缺失，总体只能 `UNKNOWN`，不能 `EXITED`；(b) 两次轮询之间完整经历「创建 → `setsid()` → 父进程退出 → 自己退出」的短命进程不可见，但它已退出，对 A 没有影响（它若成为被重新挂靠的僵尸，按 L3 归属并回收）。

### 3.3 身份、TOCTOU 与 pidfd（RV-03）

- **事实（不夸大）：**指纹核对与发信号是两个独立的系统调用，两者之间存在 TOCTOU 窗口。`(pid, starttime, sid, pgrp)` 只证明核对那一刻 pid 对应登记过的进程，**不能**证明信号送达那一刻仍是它；本草稿**不声称**指纹消除了全部 pid / pgid 复用风险。
- **何时相对安全：**监督器的**未回收子进程**（含被重新挂靠的子进程）：它的 pid 在回收之前不可能被复用，窗口内它至多变成僵尸，信号无副作用。风险集中在 (1) **不是监督器子进程的后代**（其父进程可随时回收它，pid 随后可能被复用），(2) **任何已被回收的 pid / pgid**。
- **pidfd 评估：**`os.pidfd_open(pid)`（Linux ≥ 5.3，Python ≥ 3.9）得到指向「此刻该 pid 对应的那个进程」的稳定句柄；`signal.pidfd_send_signal(fd, sig)` 只会发给该进程，进程已退出则 `ESRCH`，**不会**误发给复用了该编号的新进程。推荐顺序：① `pidfd_open(pid)`；② 再读 `/proc/<pid>/stat` 核对指纹；③ 一致才用该 pidfd 发信号。理由：若 pid 在 ① 之前已被复用，指纹不符；若在 ①② 之间被复用，句柄指向旧进程而指纹读到新进程，同样不符；无复用则一致。**限度：**只改善**单个进程**的身份稳定性；`pidfd_open` 或 `pidfd_send_signal` 失败（`ENOSYS` / `EPERM` / 被 seccomp 拦截）→ 该目标 `UNKNOWN`，**不降级为对非子进程的裸 pid 发信号**；`PIDFD_SIGNAL_PROCESS_GROUP` 等较新标志在本环境的可用性与 Python 暴露方式 **NOT VERIFIED**，草稿不依赖它。
- **整组信号（`killpg`）的单独安全条件：**仅当同时满足 ① 组领头仍是监督器的**未回收**子进程（组号因此被占用），② 该组由本阶段的 `setsid` 创建（外来进程无法加入其会话），③ 组内没有 `UNKNOWN` 或未归属的成员（`killpg` 无法选择对象，会打到所有成员），才可用 `killpg(pgid, sig)`。领头一旦被回收（组号可能随最后一个成员消失而复用），或组内有 `UNKNOWN` 成员 → **禁用整组信号**，改为对每个 `ALIVE` 且身份已验证的目标用 pidfd 逐个发送。
- **「指纹正确，但目标恰在信号前退出」：**这是不可消除的窗口。要求：信号结果如实记录（`sent` 对僵尸 / `gone`），**`sent` 不等于目标被该信号终止**，终止与否只以随后的 `EXITED` 观察为准；不得把 `sent` 当作终止成功。由测试 T-14a/b/c 覆盖。
- **残余风险：** pidfd 打开之前的复用只能由指纹核对捕获，不能证明无遗漏；真实的 pid 回绕复用在无特权环境难以制造（T-16 默认 NOT PLANNED）。

### 3.4 子收割者前提的两个评价维度（RV-04）

| 维度 | 问题 | 如何判断 | 状态 |
|---|---|---|---|
| **A. 系统调用与重新挂靠的实际行为** | `prctl(PR_SET_CHILD_SUBREAPER)` 是否成功、`PR_GET_CHILD_SUBREAPER` 读回什么；设置前后，被孤立后代的实际 `ppid` 是什么（监督器 / 最近的其它子收割者祖先 / 1）、监督器能否从 `/proc` 与 `waitid` 看到它 | **CPU 测试**（T-04b-A）；**不预设** `ppid` 一定是 1——监督器的祖先本身可能就是子收割者 | NOT TESTED |
| **B. 设置失败时是否必须禁止整个运行** | S0 在 `prctl` 失败时应拒绝启动（B1），还是允许运行但所有终止判定都降级、只能得到 BLOCKED（B2），或其它 | **实施策略，待负责人裁决**；不是 CPU 测试能回答的问题 | **待裁决** |

- **默认安全退路（建议，非规则）：**B1，即 S0 `BLOCKED`（`PREFLIGHT_FAILED`）。**这条没有写进、也没有获批进入冻结 R3**；冻结 R3 目前没有关于子收割者的规则。它只有走完变更流程并获负责人批准后才能成为规则。
- **与维度 A 无关的底线（来自 RV-01）：**子收割者未被验证开启时，完整性证据缺失，总体三态不得为 `EXITED`。这是判定逻辑，不依赖 B 的裁决。

## 4. 方案 A：先回收后求值（reap-first）

**机制（草案条款，不适用于冻结版）：** 每个轮询周期按序：
1. 对每个已登记的直接子进程 `waitpid(pid, WNOHANG)`（具体 pid，**不用 `-1`**）。返回该 pid → **立即**把退出状态写入内存记录 `exit_record`（退出码或信号、`CLOCK_BOOTTIME` 时刻）并标记已回收；返回 0 → 尚未退出。
2. 按 3.2 的谱系规则发现目标并扫描 `/proc`；`ppid` 为监督器、已归属、指纹验证通过的重新挂靠**僵尸**后代 → `waitpid(该 pid, WNOHANG)` 回收，状态记入 `exit_record`。
3. 按 3.1 求三态：**A 为真 ⇔ 总体 `ALIVE`**（步骤 1 中有直接子进程尚未退出，或步骤 2 中存在被证实未退出的目标）；总体 `UNKNOWN` 时 A 没有取值。条件 (1) 改述为「直接子进程尚未退出」。

**优点：** 与 R3 现有的 `waitpid(WNOHANG)` 轮询（§11.1(c)5）一致，Python 的 `Popen.poll()` 本来就是这种行为；回收与观察一步完成；僵尸不会累积。
**缺点 / 风险：** 观察有副作用（回收会消耗状态），所以必须在回收瞬间保存退出状态；回收后 pid 被释放，复用风险窗口提前；与 `subprocess.Popen` 混用时必须统一由同一处回收，否则 `Popen` 会误判；轮询里的回收一旦放宽到 `-1` 就会误回收其他进程（必须严格按 pid）。

## 5. 方案 B：非消耗式观察（observe-then-decide）

**机制（草案条款，不适用于冻结版）：** 每个轮询周期**只观察，不回收**：
1. 对每个已登记的直接子进程 `waitid(P_PID, pid, WEXITED|WNOHANG|WNOWAIT)`：无状态变化 = 仍在运行；有结果 = 已退出（状态保留在内核，**未被消耗**）。
2. 按 3.2 的谱系规则发现目标并扫描 `/proc`；僵尸成员只观察，不回收。
3. 按 3.1 求三态：**A 为真 ⇔ 总体 `ALIVE`**（步骤 1 中有直接子进程无状态变化，或步骤 2 中存在被证实未退出的目标）；总体 `UNKNOWN` 时 A 没有取值。
4. 回收**一律推迟到 T5**，只按具体 pid、指纹验证通过后回收，此时退出状态仍在内核里（也可由 `waitid` 的结果读取）。

**优点：** 观察与回收分离，轮询不改变系统状态，竞态分析更简单；退出状态不依赖监督器内存；对「求值顺序」不再敏感。
**缺点 / 风险：** 僵尸在整个宽限期内保留，直到 T5；需要额外的 T5 回收步骤正确执行；`waitid(P_ALL, …)` 会窥探任何子进程的状态变化，**必须只用 `P_PID`**；`WNOWAIT` 对已停止 / 恢复状态的行为不在本草稿范围；实现者容易漏掉 T5 而留下僵尸。

## 6. 两方案与基线的逐项比较（草案判断，须由受控测试验证）

基线 = 冻结 R3 的字面 A（G1/G2 已证明在若干读法下失败）。「预期」是按机制推断的，**不是测试结果**。

| 考虑项 | 基线（R3 字面） | 方案 A | 方案 B |
|---|---|---|---|
| 已退出未回收的直接子进程 | A 为真（错）；NOREAP / EVAL_THEN_REAP 读法错误升级 | 回收后 A 假；退出状态在回收时保存 | `waitid` 看到已退出，A 假；状态留在内核 |
| 进程组只剩僵尸成员 | 条件 (2) 仍成功（错） | `/proc` 状态 `Z` 不计入，A 假 | 同 A |
| 活跃后代与僵尸后代并存 | 条件 (2) 全真，无法区分 | 只要有非 `Z` 目标 A 真；僵尸后代按 pid 回收 | 只要有非 `Z` 目标 A 真；僵尸后代 T5 回收 |
| 被重新挂靠的后代 | 条件 (3) 未规定是否排除僵尸，字面上僵尸后代也是「后代」（有歧义） | 子收割者 + 谱系登记（3.2）+ 指纹；活的 `ALIVE`，僵尸回收 | 同 A（观察，T5 回收） |
| SIGTERM 到宽限截止竞态 | EVAL_THEN_REAP 读法在宽限点出错 | 先回收后求值，无顺序依赖；SIGKILL 前复核 | 纯观察，无顺序依赖；SIGKILL 前复核 |
| PID / PGID 复用 | 未处理 | 指纹 + pidfd（单进程）；整组信号仅在 3.3 的条件下；**TOCTOU 窗口仍在，不声称消除** | 同 A（回收推迟到 T5，复用窗口更晚开启；同样不声称消除） |
| 跨会话后代（`setsid()`） | 条件 (3) 只看 `ppid`==监督器，被重新挂靠前的跨会话后代不可见（歧义） | 谱系闭包 + 连续登记 + 封闭世界排除法；归属不明 → `UNKNOWN` | 同 A |
| 观察 / 身份 / 范围不能证明 | 未定义，可能被当作 A 为假 | `UNKNOWN` → BLOCKED，不发信号 | 同 A |
| 误回收其他进程 | T5 的 `waitpid(-1)` 会误回收监督器的其他子进程（**基线缺陷**） | 只对登记 pid；若退化为 `-1` 同样会误回收（实现风险） | 轮询零回收；T5 只对登记 pid（实现风险较小） |
| 对 `/proc` 的依赖 | 条件 (3) 已依赖 | 依赖 | 依赖 |
| 与现有 R3 文字的改动量 | — | A 的定义、T3、T5 | A 的定义、T3、T5（增加「T3 只观察」） |
| 对 `subprocess.Popen` 的兼容 | — | 与 `Popen.poll()` 同行为，容易对齐 | 需自己调用 `waitid`（`Popen` 不提供），监督器要自管子进程 |

**起草者倾向（非决定、非约束）：**方案 B 把「观察」与「回收」分开，竞态与误回收风险更小，我倾向于 B；但方案 A 与 `Popen.poll()` 和现有 R3 轮询文字更贴近、实现更简单。两者的真实差别应由第 7 节的同一套受控用例裁决，而不是由偏好裁决。
