## 2. E1 — 目标进程归属安全

**被测代码：**CPU-001 的 `ArmCommon._discover()` 中的 `sid_hint` 与 `closed_world_orphan` 路径（臂 CA、CB，**原样**）；另加**实验变体**（非 CPU-001 的臂，不替代它们）`CA-S`、`CB-S`（"strict attribution"）：`sid_hint` 仅当根进程是**独立会话的领头**且其会话不是监督器自己的会话时使用；不再使用封闭世界孤儿归属——`ppid` 为监督器的未登记进程，若其 `starttime` 早于阶段根则忽略（不可能是阶段后代），否则 `UNATTRIBUTABLE`→`UNKNOWN`；辅助进程的后代登记为 `aux_family`（既非目标也不使 `UNKNOWN`）。变体的可用性代价（更多 `UNKNOWN`）会如实记录。

**会话机制先行核实（S1，REAL_KERNEL）：**对一个监督器的非阶段子进程尝试 `setpgid(其pid, 阶段进程组号)`；独立会话的领头进程之外的进程无法被移入该会话。预期：`EPERM`。同时核对：阶段会话中的每个成员，其祖先链都能追到阶段根（或为已重新挂靠的后代）。若内核允许非阶段进程加入阶段会话，则用例 BLOCKED 并报告，不得继续假设。

**拓扑与预期（真值由台架自建的进程树与独立 Oracle 给出）：**

| 用例 | 拓扑 | 独立真值 | 预期（所有臂统一的安全判据） |
|---|---|---|---|
| E1-P1 | 阶段根 R（独立会话）→ C（`setsid`）；R 退出前已轮询登记 C（连续登记） | C 运行中，属于阶段 | C 被识别为目标：`ALIVE`→升级→只向 C 发 SIGKILL；最终 `EXITED`；C 状态 `signal 9` |

## 3. E2 — CA 与 `subprocess.Popen` 的兼容性

被测：**真实的 `subprocess.Popen`**（`start_new_session=True`，与 R3 一致）作为阶段根；臂 CA 登记它并用其 `waitpid(pid, WNOHANG)` 轮询。独立真值：子进程自身声明的退出码（7）或台架施加的信号（SIGKILL=9、SIGTERM=15）。**分别检查两个状态**：CA 的自有退出记录（`exit_status`）与 Popen 的内部状态（`returncode`，经 `poll()` / `wait()`）。

| 用例 | 步骤 | 判据 |
|---|---|---|
| E2-00 对照 | 仅 Popen：退出 7 / 被 SIGKILL / 被 SIGTERM 终止，`wait()` | `returncode` = 7 / −9 / −15（有效性对照，必须 PASS 否则 BLOCKED） |
| E2-01 | CA 先轮询并回收（退出码 7），随后 `p.poll()`、`p.wait()` | C1：CA 记录 = `exit 7`；C2：Popen `returncode` = 7；C3：无双重回收（第二次等待得 `ECHILD`/由 Popen 内部吞掉，**不得**产生第二份真实状态）；C4：无残留僵尸、无 `ResourceWarning` |
| E2-02 | 同上，目标被台架 SIGKILL | CA 记录 = `signal 9`；Popen `returncode` = −9 |
| E2-03 | 同上，目标被 **CA 自己的信号路径**发 SIGTERM 终止 | CA 记录 = `signal 15`；Popen `returncode` = −15 |
| E2-04 | **Popen 先**：`p.wait()` 取得状态，然后 CA 轮询 | C1：CA 不得在无状态时断言 `EXITED` 并附带错误状态——预期 `UNKNOWN`（`ECHILD` 冲突）或明确的「状态属他人」；Popen 真值保持 |
| E2-05 竞态（N=50） | 线程中 `p.wait()` 与主线程 CA 轮询并发，子进程在随机时刻退出 | 每次：恰有一方取得真实状态；C1 不得出现 CA 的错误记录；C2 记录 Popen 是否取得真实状态；无死锁、无异常、无残留 |
| E2-06 | CA 回收后调用 `p.terminate()` / `p.kill()` / `p.send_signal()` | INSTRUMENTED：`os.kill` 调用次数应为 0（不向可能被复用的 pid 发信号） |
| E2-07 变体 CA-P | **缓解检查（非 CPU-001 的 CA）：**监督器让 Popen 成为**唯一**的回收者，CA 的状态读取自 `p.poll()` / `p.returncode` | 与 E2-01/02/03 同判据，预期全部成立 |
| E2-08 对照 CB | CB 观察→(a) CB 的 T5 回收→再 `p.poll()`；(b) CB 观察→`p.poll()` 回收→CB 再轮询 | 记录两种顺序下 Popen 的 `returncode` 与 CB 的三态 |

**判定：**C1∧C2∧C3∧C4 全部成立 = PASS；任一不成立 = FAIL。按本判据，**CA 先回收、Popen 后读取**的顺序预期会 FAIL C2——这是需要如实记录的兼容性事实，而不是需要被"修正"的预期。普通用例各 5 次，E2-05 为 50 次。

## 4. E3 — CB 遗漏 T5 的影响

故障注入：跳过 CB 的 T5（`SIMULATED` 的是"遗漏"这一故障；僵尸、`/proc`、`waitpid` 的行为是 `REAL_KERNEL`）。不得遗留不受控进程：每个用例末尾由台架按 pidfd + 指纹清理并做残留扫描。

| 用例 | 步骤 | 判据 |
|---|---|---|
| E3-01（臂 CB；对照 CA） | 5 个阶段节点陆续退出（码各异）；臂观察后**不执行 T5**；每 0.5 s 采样 6 s：`/proc` 状态、`kill(pid,0)`、`waitid(WNOWAIT)`、pid 是否仍占用；之后**迟到的 T5** | **预测检查**：CB 的僵尸在采样窗口内持续为 `Z` 且 `kill(pid,0)`=成功；CA 无僵尸。**恢复判据（必须成立才 PASS）**：迟到的 T5 回收全部、状态等于真值、残留 = 0 |
| E3-01b（台架，K=300） | 300 个直接子进程退出而不回收：记录占用的 pid 槽、`/proc` 条目、`pid_max`、`RLIMIT_NPROC`、是否仍能继续创建进程；随后逐 pid 回收并核对状态 | 描述性；回收后残留 = 0 才 PASS |
| E3-02a（臂 CB 与 CA） | 监督器（一个由台架 fork 出的子进程 SUP）运行臂、阶段节点（含一个已退出、一个运行中忽略 SIGTERM 的节点、一个登记的辅助诱饵）；SUP 被台架 `SIGKILL`（**异常退出，无 T5，无清理**）；外层台架开启子收割者，成为孤儿的新父进程 | **恢复判据**：外层仅凭 pidfd + 指纹找到全部阶段进程并清理（运行中的用 pidfd 杀死；僵尸逐 pid 回收），残留 = 0；**预测检查**：CB 未回收僵尸的状态在外层可读且等于真值，而 CA 已回收的状态不可恢复；**安全判据**：哨兵与诱饵（其状态由台架读取应为真值）不受影响，没有信号发给非目标 |
| E3-02b | 同上但外层**关闭**子收割者 | 记录孤儿被谁收养（预期 pid 1）、僵尸是否由其清理、运行中孤儿是否继续存活；台架仍按 pidfd 清理，残留 = 0 |
| E3-03（臂 CB-nofinally / CB-finally） | 在观察之后、T5 之前注入异常；一臂不保护，一臂用 `try/finally` 调用 T5 | **判据**："异常路径不遗留僵尸"：保护臂 PASS；未保护臂预期 FAIL（有僵尸遗留）——如实记录 |

普通用例各 5 次。
