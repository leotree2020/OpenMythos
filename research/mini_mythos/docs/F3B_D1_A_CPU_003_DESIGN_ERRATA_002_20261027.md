## 1. ERRATA-002-01 — 歧义负例的验收逻辑

### 1.1 冲突是什么

ERRATA-001 把「A 类歧义负例」定义为「台架知道真相、故意让机制无法区分」，并规定其中**所有**确定答案都计 `X`（FAIL）。但 E1-C 明确允许**具备额外有效证据**（登记表、事件流、cgroup 成员关系）的候选机制把原本在仅轮询证据下不可区分的进程判定清楚。两条规则冲突：如果某机制确实**能证明**归属，对它而言该场景不是"歧义"，正确的确定答案不应被判 FAIL；反过来，没有证据的机制作出确定判断，才应被判 FAIL。**歧义不是场景的固有属性，而是「场景 × 机制证据能力」的属性。**

### 1.2 修正：按候选机制预先分类

**(a) 证据能力声明（Evidence Capability Declaration，ECD）。**每个候选机制在执行前登记其**允许使用的证据来源**及每个来源的可用条件和可验证性：

| 证据来源 | 内容 | 是否构成证明 |
|---|---|---|
| ES-1 | `/proc` 轮询的 `ppid` 闭包 + 连续登记（每一跳在连续两次扫描里被指纹确认） | 是（对已被观察的链） |
| ES-AUX | 辅助进程登记；在辅助进程**存活时**登记其后代（`aux_family`） | 是 |
| ES-ORD | `starttime` 早于阶段根（并留出至少一个时钟滴答的余量）⇒ 不可能是阶段后代 | 是（证明**非阶段**） |
| ES-SIDV | 阶段根经 S0 验证为独立会话领头且 `sid` ≠ 监督器 `sid` 之后，同会话成员必为阶段后代 | 是（前提必须已被验证） |
| ES-REG | 创建入口登记（O-2）；S0「无未登记子进程」检查 | 只证明"经入口创建"，**不证明**未登记进程是否阶段后代 |
| ES-EVT | 完整的 fork / exit 事件链（proc connector，O-5）；缓冲溢出使证据失效 | 是（链完整时） |
| ES-CG | cgroup 成员关系（O-4） | 是（设施可用时） |
| ES-CW | 封闭世界**声明**（"监督器没有其它子进程"） | **否**（不可验证） |
| ES-SID | `sid_hint` 而未经 S0 验证独立会话 | **否**（前提未验证） |

**(b) 证明规则。**机制给出的**每个确定答案**必须附带 `proof = {rule_id, premises}`，其中 `rule_id` 属于该机制的 ECD，且 `premises` 能被台架用**独立数据**复核（例如 ES-ORD 的前提 `starttime(P) < starttime(root)` 由台架用谱系账本中的出生指纹核对）。**没有合法引用的确定答案 = 猜测 = FAIL，即使碰巧正确。**

**(c) 三类预先分类。**对每个（场景 × 候选机制），在执行前按"台架谱系账本给出的真相 + 该机制的 ECD + 证明规则"静态推出：

| 类别 | 含义 | 期望 |
|---|---|---|
| **PROVABLE** | 证据足以证明归属（目标或非目标） | 正确的确定答案 |
| **UNPROVABLE** | 证据不足以证明 | `UNKNOWN`（不得猜测） |
| **BENCH_UNVERIFIABLE** | 台架自己无法建立真实归属（创建记录丢失等） | 试验为台架 BLOCKED（`B`）；不计入任何比率 |

**(d) 判定。**

| 类别 | 机制输出 | 实验判定 | 结果类 |
|---|---|---|---|
| PROVABLE | 正确的确定答案 + 合法引用 | **PASS** | R |
| PROVABLE | 确定答案但错误，或正确却无合法引用（猜测） | **FAIL** | X |
| PROVABLE | `UNKNOWN` | 安全上无错；**可用性缺失**（单独报告，不算安全 FAIL） | U-unexp |
| UNPROVABLE | `UNKNOWN`（或 `INTRUDER` 诊断，不发信号） | **PASS** | U-exp |

| BENCH_UNVERIFIABLE | — | 台架 BLOCKED | B |

**(e) 运行期证据失效的降级。**PROVABLE 场景里，若机制所依赖的证据在该试验中**失效**（例如 proc connector 缓冲溢出），机制应降级为 `UNKNOWN` 并给出失效原因码；仅当台架**独立确认**了该失效（台架注入的故障，或台架自己测得的溢出）时，该试验才算"降级 PASS"并记为 U-unexp（可用性缺失）；没有独立确认的 `UNKNOWN` 就是普通 U-unexp。分类本身**不因此改变**。

**(f) 硬门槛不变。**非目标误信号 = 0；非目标误回收 = 0；不得在真目标仍存活时伪造 `EXITED`；归属无法确认时不猜测。任何一次都是 FAIL，不能被分类或可用性抵消。

## 2. ERRATA-002-02 — Janitor 登记持久化竞态

### 2.1 问题

ERRATA-001 的清理设计是"创建牺牲进程 → 观察者登记 → Janitor 崩溃后读取登记"。若观察者在 `fork()` 之后、**持久化登记完成之前**死亡，Janitor 找不到该进程；而该进程若已开始运行实验动作（甚至创建后代），就成为**无人负责的自由运行进程**。ERRATA-001 的"孙代进程由其创建节点在行动之前自报"同样留有"创建 → 自报"之间的自由运行窗口。

### 2.2 创建—登记—释放协议（GATED-SPAWN，仅限台架的牺牲进程）

**角色：**O 观察者（唯一写登记文件 REG 的进程）；J Janitor（外层运行脚本，只读 REG）；C 创建者（O 或已登记释放的节点）；N 新进程。

**协议步骤：**

1. **意向记录先于 `fork()`：**O 先 `os.write` 追加 `INTENT{run_id, node_id, creator, seq}` 到 REG（以 `O_APPEND` 打开，单次 `write` 一整行）。
2. **门（gate）：**为每个新进程预先创建一对管道 `gate_r` / `gate_w`；`gate_w` 只由 O 持有（`O_CLOEXEC`，不被 O 的其它子进程继承）。
3. **创建：**C 调用 `fork()`。**N 的第一个动作是关闭继承来的 `gate_w`，随即阻塞地读 `gate_r`**（带超时 `T_gate_max`，建议 10 s）。**在收到明确的 RELEASE 字节之前，N 不执行任何实验动作、不 `exec` 节点程序、不创建后代。**
4. **登记：**`fork()` 在 O 中返回后，O 取得 `pid`；O 的**直接子进程**在未被回收前其 pid 不可能被复用，因此身份由内核父子关系保证。O 立即 `pidfd_open(pid)`，读 `/proc/<pid>/stat` 核对 `starttime/sid/pgrp`，然后 `os.write` 追加 `REGISTERED{node_id, pid, starttime, sid, pgrp}`（一整行，以换行结尾）。
5. **释放：****只有当 `REGISTERED` 的 `write` 成功返回之后**，O 才向 `gate_w` 写 `RELEASE`。N 收到后才继续（`exec`）。
6. **失败关闭（fail-closed）：**登记失败（`pidfd_open` / `starttime` 核对 / REG 写入失败，例如 `ENOSPC`）、身份核对失败、O 的登记超时 `T_reg`（建议 2 s）→ O **不发送 RELEASE**，而是关闭 `gate_w`（或写 `ABORT`）；N 读到 `EOF`、`ABORT` 或自身 `T_gate_max` 超时 → **自行退出**（`exit(111/112)`）。O 对自己的直接子进程可凭内核父子关系 `pidfd_send_signal` 兜底，并用具体 pid `waitpid` 回收。该试验记为**台架 BLOCKED**。
7. **观察者死亡：**O 一旦死亡，所有 `gate_w` 随之关闭，所有未释放的 N 读到 `EOF` 并**自行退出**——没有"自由运行窗口"，无需 J 去猜测它们。
8. **后代：**已登记并释放的节点要创建后代，必须走**同一协议**：节点向 O 请求**门票**（O 经已有的 Unix 套接字，用 `SCM_RIGHTS` 传来 `gate_r`；`gate_w` 留在 O）；节点 `fork()`，子进程先关闭多余描述符并阻塞在门上；节点把 `(pid, starttime)` 报告给 O；O `pidfd_open`、核对、写 `REGISTERED`、再 RELEASE。节点本身**不能**释放自己的后代。
9. **陌生进程 / 被测监督器内部创建的进程：**E1-B 中"绕过入口"创建的陌生进程，以及被测监督器进程里的辅助子进程，由**台架桩代码**（不是被测机制）通过同一门票协议创建并登记，角色为 `stranger` / `aux`。台架里**不存在**不经此协议创建的牺牲进程。
10. **Janitor 的行为：**J 只对**同时存在 `INTENT` 与 `REGISTERED`（且 `REGISTERED` 行完整）** 的记录行动：先 `pidfd_open(pid)`，**再**读 `/proc/<pid>/stat` 的 `starttime` 与记录比较，一致才 `pidfd_send_signal(SIGKILL)`，不一致 → 不发信号、记录、BLOCKED。**只有 `INTENT`、没有 `REGISTERED` 的记录，J 不发信号**（那样的进程按步骤 7 已经自行退出；J 只做存在性诊断）。J **不能**根据命令行令牌猜测归属（ERRATA-001 §3 第 3 条不变）。
11. **pidfd 不能靠保存的整数恢复：**文件描述符是进程私有的，观察者死亡后它们随之关闭，REG 里保存的 `pid` 和 `starttime` 才是可恢复的身份。J 必须**重新** `pidfd_open` 并重新核对，不得假定任何旧描述符仍有效。
12. **撕裂的末行：**REG 末行若缺少换行符，视为**撕裂**，J 忽略它。因为 RELEASE 只在 `REGISTERED` 的 `write` 成功**之后**发出，撕裂的 `REGISTERED` 行意味着对应的 N 从未被释放（步骤 7 使其自行退出）——协议不变量见 2.3。

### 2.3 不变量与可验证性

| 编号 | 不变量 | 如何保证 / 如何检查（未来） |
|---|---|---|
| **I1** | 任何**已释放**的进程，其 `REGISTERED` 记录已在 RELEASE 之前完整写入 REG | 协议顺序（步骤 4 → 5）；检查：REG 与进程树逐项对账 |
| **I2** | 任何**未释放**的进程不执行实验动作，且在 O 死亡 / 中止 / 超时后自行退出 | gate 读 + EOF / ABORT / `T_gate_max`；检查：O 死亡注入后在 `T_gate_max` + 余量内计数残留 |
| **I3** | J 只对完整的 `INTENT`+`REGISTERED` 记录、经重新验证身份后发信号 | 步骤 10、11 |
| **I4** | 台架中不存在不经 GATED-SPAWN 创建的牺牲进程 | 台架代码审查 + 运行结束时的进程树对账（任何未登记的、属于运行令牌的进程 → 残留诊断） |

**`fork()` 调度顺序：**`fork()` 返回时子进程可能先于或晚于父进程运行。协议对此**不依赖顺序**：子进程无论何时运行，第一步都是阻塞在门上；父进程无论何时返回，都在登记之后才释放。子进程在门上阻塞期间即使 O 在 `fork()` 返回前死亡，`gate_w` 随之关闭，子进程读到 `EOF` 退出。唯一需要注意的窗口是**子进程自己关闭继承来的 `gate_w` 之前**：此时 O 若死亡，`gate_w` 仍被子进程自己持有，因而不会立即出现 `EOF`——但子进程的**第一个动作**就是关闭它，之后读 `gate_r` 立即得到 `EOF`；若这一步被卡住，也有 `T_gate_max` 超时兜底。

### 2.4 最极端情形：观察者在持久化登记之前死亡

按步骤 1–7：O 在 `fork()` 之后、写 `REGISTERED` 之前死亡 → `gate_w` 关闭 → N（尚未释放）读到 `EOF` 并自行退出；REG 里只有 `INTENT`；J 不对它发信号。**没有自由运行窗口，也没有需要 J 去找的进程。**O 在 `REGISTERED` 写完之后、RELEASE 之前死亡 → N 同样 `EOF` 退出；J 发现记录对应的进程已消失或为僵尸，无需信号。O 在 RELEASE 之后死亡 → N 已登记并运行，J 按步骤 10 清理。

### 2.5 剩余风险与 BLOCKED 条件（如实标注，**不声称已完全解决**）

| 编号 | 剩余风险 | 后果 | BLOCKED / 处理条件 |
|---|---|---|---|
| R1 | 未释放的 N 在 O 死亡后**没有**自行退出（卡在不可中断睡眠、被他人 `SIGSTOP`、门读取实现缺陷） | 存在一个**未登记**的阻塞进程，J 无法凭登记找到它 | 超过 `T_gate_max` + 余量仍存在 → 令牌扫描只**诊断**（列出 pid / `starttime` / `ppid` / 状态），**不发信号**，该试验与其后运行 BLOCKED，需人工 / 负责人处理 |
| R2 | O 与 J 同时失效 | 没有自动清理层 | 报告为残余风险；人工处理 |
| R3 | `pid` 在 O 死亡到 J 重新验证之间被复用且 `starttime` 恰好相同（10 ms 分辨率） | J 可能验证通过后对错误进程发信号 | 实际概率极低但**不为零**；J 的 `pidfd_open` 先于核对；该风险写进报告 |
| R4 | `write(2)` 返回只保证数据进入页缓存，机器掉电 / 内核崩溃可能丢失 | 登记丢失 | **本设计只要求普通进程崩溃恢复，不扩展为掉电恢复工程**；掉电超出范围 |
| R5 | 已释放节点的代码缺陷导致它**不经协议** `fork` 后代 | 出现未登记的自由运行后代 | 运行结束时用 I4 对账发现：任何属于运行令牌且不在 REG 的进程 → 残留诊断、不发信号、BLOCKED。无法在运行中阻止 |
| R6 | 某处遗漏关闭 `gate_w`（被其它子进程继承） | 持有者存活时 `EOF` 不出现，N 只靠 `T_gate_max` 超时退出 | 最长未登记阻塞窗口 = `T_gate_max`；仍无实验动作，仅表现为延迟退出 |
| R7 | 观察者自身缺陷（多线程下 `fork`、描述符泄漏） | 协议被破坏 | 观察者设计为单线程、极简；单元测试在台架编写阶段覆盖（本轮不写） |

**如果仅靠用户态登记和等待协议无法严格保证某条件（R1、R2、R3、R5、R6），上表即为如实的剩余风险和 BLOCKED 条件；本文件不声称"完全消除"。**本协议不引入生产级架构改造：它只约束**台架的牺牲进程**，被测机制与真实 D1 代码不受影响。
