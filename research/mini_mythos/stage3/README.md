# Stage 3a:MoDA(深度注意力)单项实验(方案草案,待批准)

规则见根目录 `CLAUDE.md`(宪章 v2.0)。前置:阶段 2 CLOSED(2026-11-09)。本阶段只加 **一个** 机制:MoDA。参考实现是 `open_mythos/moda.py`。代码在负责人批准本方案后再写。

## 目的

检验一件事:给 Parcae 的循环核心加“深度注意力”,在**同参数、同数据、同调参次数**的条件下,是否比不加机制的 LoRA 微调更好,尤其是在异领域文本上。

**大白话**:Parcae 会把同一段网络反复跑 8 遍。现在每一遍只能看到上一遍的结果。MoDA 让它在每一遍里都能回头翻看前面**所有遍**留下的笔记,而且只看同一个词位置的笔记。我们要测的是:这种“翻旧笔记”能不能让模型猜词更准。

## 机制:MoDA-P(MoDA 的 Parcae 版)

参考实现的做法是:每层注意力在同一个 softmax 里,同时看序列上的 token,以及之前各层在**同一位置**写下的“深度 K/V”;每层输出再经过一对写投影 `k_write`、`v_write`,写进深度缓存。

迁移到 Parcae 时这样做,不修改上游代码,全部用钩子实现(和阶段 2 的 LoRA 一样):

1. **写**:循环核心有 2 层,每层每跑完一遍,就把它的输出 `h` 写进深度缓存:`k = qknorm(W_k^(j) · norm(h))`,`v = W_v^(j) · norm(h)`。`j` 是层号(0 或 1)。每层有自己的写投影,8 遍之间共享,和 Parcae 的权重共享方式一致。
2. **读**:核心层 `l` 在第 `r` 遍时,读取同一 token 位置上之前写下的全部条目。条目包括前几遍的所有层,以及本遍里更早的层。深度 8 时最多 15 条。
   - **查询**:直接用这一层原有的 `c_q` 加 qk-norm,与参考实现一致,查询和序列注意力共用。
   - **RoPE 不用算**:同一位置的查询和键旋转角度相同,点积里会抵消。
   - **输出**:先按头乘以门控 `g_h`,再经过这一层原有的 `c_proj`,加到注意力输出上。
3. **门控初始化为 0**:第 0 步时模型和原生 Parcae **逐位相同**。
4. **写投影的初始化**:复制“下一个读它的层”原有的 `c_k`、`c_v`。这样深度键一开始就和查询处在同一空间,不需要从随机状态学起。

**与参考实现的唯一偏离**:深度条目用**单独的 softmax**,再通过门控加到输出上,而不是和序列 token 共用一个 softmax。理由有两点:
- 共用 softmax 时,即使深度 V 为 0,也会把序列注意力的权重压小,第 0 步就不等于原生模型,对照不干净。
- 共用 softmax 需要序列注意力的 log-sum-exp。上游用的是 flash-attn,钩子拿不到这个值;要拿到,只能把 T×T 注意力重算一遍,计算量翻倍。

共用 softmax 的版本留作后续变体,本阶段不做。

**训练时的细节**:沿用阶段 2,每步 8 遍,只对后 4 遍反传。前 4 遍写入的条目,状态本身不带梯度,但**写投影仍然计算梯度**(在钩子里临时打开梯度)。不这样做的话,写投影只能从一半的条目里学。

**参数量**:写投影 2 层 × (768×768 + 768×768) = 2,359,296;门控 2 层 × 6 头 = 12。合计 **2,359,308**。

**额外计算**:每层每遍多 2 次 768×768 投影,外加每个 token 对 ≤15 个条目的点积。估计核心部分多 10–20% 计算,实测后报告。

## 对照

| 组 | 内容 | 可训练参数 |
|---|---|---|
| N 原生 | Parcae-140M,不训练 | 0 |
| **C-LoRA-r28**(主对照) | 和阶段 2 相同的 LoRA,只把 rank 改成 28 | 2,325,624(比 MoDA 少 1.4%) |

两组的同预算条件:训练 token 相同(5000 万,即阶段 1 训练语料全部,1 遍),都搜 3 个学习率(1e-4、3e-4、1e-3,只看开发集,选 4 个领域平均 NLL 最低的),都跑 2 个种子(0 和 1)。其余训练设置照搬阶段 2:bf16、序列长 1024、全局批 32、AdamW、5% 预热后余弦衰减、梯度裁剪 1.0。

## 评估

- 方式与阶段 2 相同:FP32,关闭 TF32,深度 8,不加 BOS,2 个初始状态副本,初始状态在 CPU 上生成。
- 开发集:4 个领域各 100 个窗口。测试集:4 个领域各 200 个窗口。
- **主指标**:测试集上逐窗口配对的 NLL 差,`M − C-LoRA-r28`,按领域报告均值和 95% bootstrap CI。负数表示 MoDA 更好。
- 只报告、不作门槛的项目:
  - `M − N`;
  - 训练后门控的大小、深度注意力的熵;
  - 深度 16 时的开发集分数,看多跑几遍时 MoDA 是否更有用;
  - 实测 tokens/s 和每 token 计算量。

## 通过标准(看结果前冻结)

**第一步,开发集关口**(不碰测试集)。两个种子都要满足:MoDA 在 3 个异领域(c4、wikitext、books)上的平均开发集 NLL 低于 C-LoRA-r28。不满足就判 **FAIL**,测试集不用。

**第二步,测试集**。冻结两个候选:MoDA 和 C-LoRA-r28,各自取选中学习率下 seed 0 的模型。各在测试集上评一次,并记入 `stage1/TEST_LOG.md`。**PASS** 需要同时满足:
1. 3 个异领域里至少 2 个满足:`M − C` ≤ −0.003 nats,且 CI 上界 < 0;
2. 3 个异领域的平均 `M − C` ≤ −0.003;
3. 4 个领域里没有一个明显变差,即 CI 下界 > 0 且均值 > +0.003 的领域一个都没有;
4. 效果大于训练噪声:开发集上,两个种子的 `M − C`(异领域平均)方向一致,并且各自的绝对值都大于两个种子之间的差。

只满足部分条件的,如实报告为 FAIL,并写明哪几条满足了。

门槛 0.003 的来源:阶段 2 实测,每领域 100 个窗口的 CI 半宽约 0.001–0.0015,无机制微调的变化在 ±0.003 以内。测试集每领域 200 个窗口,CI 会更窄。

## 实现计划(批准后写)

| 文件 | 作用 |
|---|---|

| `test_stage3.py` | 见下 |

开始前在 CPU 上用随机小模型通过以下测试:
1. 门控为 0 时,输出与原生模型逐位一致;
2. 钩子实现与一个独立写的朴素循环实现,在数值上一致(误差 < 1e-6);
3. 因果性:改动第 t+1 个 token 不影响第 t 个及之前的输出;
4. 训练、续训、评估、汇总端到端跑通;
5. 参数量与上表一致。

另外在真实模型上,用 CPU 跑几个窗口,确认门控为 0 时与阶段 1 的逐窗口 NLL 一致。

## 预算与停止条件

- **训练**:8 次 × 5000 万 token。按约 3.5–4 万 tokens/s 估算,约 3–3.5 小时。
- **其他**:环境和数据约 0.5 小时,评估很快。
- **总计**:约 4 小时。RTX 4090 按 $0.69/小时,约 **$3**。**建议上限 $8**,到了就停下报告。
- CPU 测试没全过,不租 GPU。GPU 上门控为 0 时与原生不一致,先停下排查。
- 路径或导入问题 30 分钟内修不好,就停下报告。
