# 机制卡片(Mechanism registry)

更新:2026-11-09。每个机制一张卡片,记录它是什么、接在 Parcae 的哪里、要多少参数和计算、证据、优缺点,以及**在什么情况下可能有用**。每跑完一次实验就更新对应卡片。证据只认宪章 v2.0 下的实验:有同预算对照、有新数据。旧实验只作线索。

## 全部机制清单(做过的和没做过的)

“贴合 Mythos”是指 OpenMythos README 里“Mythos 可能是什么”那张表的位置:
- **核心**:表里明确列出,并说“很可能”;
- **可能**:表里列出,但只说“可能 / 怀疑”;
- **外围**:不在表里,属于扩展或效率优化。

“对 Parcae 派生”是指,在 Parcae-140M 权重的基础上加这个机制,能不能做、值不值得做。

**这张表说明三件事**:
1. Mythos 假说的“核心”里,**第 1、2 条 Parcae 已经有了**。所以 Parcae 本身就是“最像 Mythos 的公开小模型”。
2. 核心里**还缺第 4、5 条**:
   - 第 5 条测过,在 Parcae 上没有空间;
   - 第 4 条在新标准下**还没测过**,而且它最便宜。它是最“贴合 Mythos”的待测项。
3. 我们的评测只看文本 NLL,但 Mythos 假说说的好处是**多步推理、组合泛化、深度外推**,NLL 未必能体现。将来要加一个小的推理类评测,例如合成的多跳任务或完整的 CORE。不然第 4、6、12 条即使有用,也可能测不出来。

## 总体结论(到阶段 3a 为止)

1. **冻结的 Parcae 很难靠微调变好。**
   - 在预训练同类数据上做无机制微调:2000–2400 万 token,LoRA r8、r28 或全参数,各领域变化都在 ±0.0015 nats 以内(阶段 2、3a)。
   - 机制要胜出,就得提供模型现在**做不到**的事,而不是“多一点容量”。
2. **唯一稳定有效的“旋钮”是多跑几轮。**
   - 深度从 8 加到 16,改善 0.001–0.0025 nats;加到 32,改善 0.002–0.003。
   - 代价是计算量变成 1.7 倍、3 倍(阶段 0、3a)。
3. **效果可能是“分情况”的。** MoDA 只在书籍上有小而真实的效果(−0.0013),其他领域为 0。所以每张卡片都要记录“在哪些领域、深度、长度上有效”。

## 能不能像搭积木一样组合机制?

**工程上可以,科学上要逐块证明。**

**工程层面**:所有机制都用同一种接口来写:钩子 + 一组参数 + “初始时等于原生”。现在的 LoRA 和 MoDA-P 已经是这样:
- 可以同时挂多个,互不修改代码;
- 每个都能单独拆下;
- 门控为 0 时整个模型和原生 Parcae 完全一样。

这一点以后对每个机制都写成硬性要求。

**科学层面**,有三个难点:
1. **效果一般不能相加。** 两个机制可能在补同一个缺口,加在一起不比单个好;也可能互相干扰。必须实测。办法是 2×2 设计:A、B、A+B、对照,同预算,直接测“交互项”。
2. **“在某些情况下才加入”本身就是一个机制,也就是路由器。** 它需要一个推理时拿得到的信号来判断“现在是什么情况”,比如文本类型、当前轮数、模型的不确定度。阶段 0 的自适应深度就是这类尝试,结果是负的:连“偷看答案”的理想路由都不比固定 8 轮更值。分情况开关要先证明“如果开关完美,能赚多少”(理想路由上限),再去学开关。
3. **前提是有积木。** 目前通过新数据检验的机制数量是 0。所以顺序是:先找到至少两块单独有效的积木,再试组合。这与宪章第 3.6 条一致。

**结论**:可行,但要先有能用的积木。卡片里的“有效情况”字段,就是为将来“分情况组合”攒证据。

## 卡片

格式:是什么 / 接在哪里 / 参数与计算 / 初始等于原生? / 证据与状态 / 优点 / 缺点 / 可能有用的情况 / 与其他机制的关系。

### 1. 多跑几轮(深度外推,原生能力,不是新机制)
- **是什么**:推理时把循环核心多跑几遍,例如 8 → 16 → 32。
- **参数与计算**:0 参数;计算 1.7×(16 轮)、3×(32 轮)。
- **证据**:阶段 0 新数据上,16、32 轮改善 0.2–0.3% 困惑度。阶段 3a 开发集上,16 轮改善 0.001–0.0025。同分布的 FineWeb 上不显著。
- **优点**:不用训练,稳定。
- **缺点**:收益小、成本高,性价比低。
- **可能有用的情况**:异领域文本(wikitext、c4)。
- **关系**:是所有“循环相关”机制的参照线。一个机制如果让“多跑几轮”更划算,就有价值。

### 2. 自适应深度 / ACT(OpenMythos `ACTHalting`)
- **是什么**:每个 token 自己决定跑几轮。
- **证据**:**CLOSED,负结果**(阶段 0)。固定 8 轮已经在“质量-计算”曲线上很靠前;理想路由也没有空间。
- **缺点**:省不下计算,还要额外的开销。
- **重新打开的条件**:先有机制让深度收益明显变大。

### 3. MoDA 深度注意力(OpenMythos `moda.py`)→ 阶段 3a 的 MoDA-P
- **是什么**:每一轮回头看前面所有轮在同一位置留下的“笔记”。
- **接在哪里**:核心块注意力;单独 softmax,门控初始为 0。
- **参数与计算**:236 万参数;训练只慢约 2%。
- **证据**:**FAIL**(阶段 3a)。相对同参数 LoRA,书籍 −0.0013 [−0.0021, −0.0005],其他领域为 0。门控几乎没打开,深度输出约占注意力输出的 1.5%。旧实验(16 篇 WikiText 训练)在 AG News 上变差 0.19–0.26。
- **优点**:便宜;实现干净,可以拆下。
- **缺点**:冻结的 Parcae 不怎么用它。可能因为 Parcae 的注入式更新(见第 6 条)已经把需要的信息带在状态里了。
- **可能有用的情况**:书籍(长篇叙述)。
- **关系**:和“循环编号”互补:MoDA 回看过去,循环编号告诉模型“现在是第几轮”。

### 4. 循环编号 / 深度 LoRA(OpenMythos `loop_index_embedding`、`LoRAAdapter`)→ 阶段 3b 候选
- **是什么**:让共享权重知道“现在是第几轮”,每一轮做不同的事。OpenMythos 有两种做法:
  - **(a) 正弦编号**:把轮数的正弦信号加到状态上,0 参数;
  - **(b) 深度 LoRA**:LoRA 的 A、B 在各轮之间共享,每一轮再乘一个可学的缩放向量。
- **接在哪里**:核心块。
- **参数与计算**:
  - (b) rank 16 时约 44 万参数,每轮缩放只多约 1.6k 参数;
  - 计算几乎不增加。
- **初始等于原生?**
  - (b) 可以:B=0、缩放=1 时,与普通 LoRA 完全相同;
  - (a) 直接加正弦信号会改变冻结模型,要加门控。
- **证据**:没有新数据结果。旧实验(16 篇 WikiText)里:
  - 循环编号不如同参数量的共享偏置;
  - 共享 LoRA 已经拿到按深度 LoRA 约 70% 的收益。
  - 线索偏弱。
- **优点**:很便宜。直接针对“权重共享导致各轮只能做同一件事”的限制。
- **缺点**:Parcae 训练时每条序列的轮数是随机的(泊松分布,平均 8),它被训练成**不依赖**轮数,未必用得上编号。超出训练轮数时(例如 16 轮),缩放只能沿用最后一轮的值。
- **可能有用的情况**:深度外推;需要“先粗后细”的文本。
- **关系**:如果它让第 9–16 轮更有用,就能和第 1 条叠加。

### 5. 普通 LoRA(对照,不是机制)
- **证据**:
  - r8 全层,2000 万 token:变化 ≤ ±0.0035;
  - r28 全层,2400 万 token:变化 ≤ 0.0014。
  - 学习率较大时变差(遗忘)。
- **用途**:所有机制的同预算对照。

### 6. 稳定注入 / LTI 注入(OpenMythos `LTIInjection`)
- **是什么**:`h ← A·h + B·e + 核心块输出`,保证 A 的谱半径 < 1。
- **状态**:**Parcae 已经内置**(对角注入 `injection_type="diagonal"`;OpenMythos 的这部分本来就引用自 Parcae 论文)。这条不当作新机制测试。
- **关系**:它让每一轮都能看到原始输入 e。这可能是 MoDA 用处不大的原因之一。

### 7. MoE 前馈(OpenMythos `MoEFFN`、`DeepSeekMoE`)
- **是什么**:把前馈层换成“路由专家 + 共享专家”。
- **接在哪里**:替换或旁挂 MLP。对冻结模型只能“旁挂”,例如在原 MLP 上加一组门控为 0 的小专家。
- **参数与计算**:参数多,每个 token 只用一部分;要负载均衡损失。
- **证据**:无。MoDA+MoE 组合的旧实验启动测试就失败了,没有结果。
- **优点**:增加容量,但不增加多少每 token 计算。
- **缺点**:阶段 2、3a 表明,**容量不是瓶颈**:更大的 LoRA 也不更好。在 2400 万–5000 万 token 上,学会路由的可能性也低。
- **可能有用的情况**:多领域混合数据。我们的训练语料是单一网页类,很难体现。
- **优先级**:低。

### 8. MLA 注意力(OpenMythos `MLAttention`)
- **是什么**:把 K/V 压缩成低秩潜变量,省推理缓存。
- **用途**:主要省显存和缓存,不是为了提高质量。替换冻结模型的注意力需要重新训练,和“派生 Parcae”的方向不符。
- **优先级**:很低;除非目标改成“相近质量、更省推理资源”。

## 建议的测试顺序(2026-11-09 更新:负责人决定转向解冻试点)

阶段 2、3a 表明,冻结的 Parcae 加小数据不太可能产生可测的收益。以后的主线改为**解冻**:原权重和机制一起训练,并与“同样解冻、同样数据、不加机制”的对照比较。冻结版保留,只作快速初筛。

1. **3b 解冻试点:MoDA-P + 全参数训练**,对照为全参数训练,每次 2 亿 token。
   - 问的是:冻结是不是 MoDA 用不上的原因?
   - 诊断指标:门控大小、深度输出占比。3a 冻结时这一占比约 1.5%。
2. 根据 3b 的结果:
   - 如果解冻后机制被用上了:用同一流程测**循环编号**(第 4 条,最贴合 Mythos)和深度 LoRA(第 6 条);
   - 如果还是用不上:基本可以说,在 Parcae-140M 这个规模上,“后加机制”的路线空间很小,需要重新讨论方向。
3. 加一个推理类小评测,与 NLL 并列报告。
4. MoE、MLA 暂不安排。
