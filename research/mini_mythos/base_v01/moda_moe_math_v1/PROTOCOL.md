## What the source implements

MoDAAttention jointly normalizes current-layer causal sequence keys and past-depth keys at the same token position with one softmax. It uses GQA head repetition and separate Q/K/V/output projections. With no depth history it uses causal scaled-dot-product attention. Depth keys written by MoDABlock have position RoPE applied; depth values do not. Histories are external arguments, not persistent module caches.

DeepSeekMoE contains always-active shared experts and top-K routed SwiGLU experts. Gate weights come from original soft scores, not optional biased routing scores. The source gate explicitly computes softmax scores in FP32, and converts sigmoid scores to FP32, even when its inputs/module are FP64. This protocol therefore does not claim the whole MoE path is FP64. Top-K membership is discontinuous at ties; derivative comparisons concern fixtures with a fixed non-tied selected branch.

The source's balance-loss formula is sum_i f_i*P_i, with hard selected counts contributing f_i and mean soft scores contributing P_i. The docstring sentence saying minimization pushes overloaded probabilities upward is incorrect; the tested formula and derivative are the authority. Record this documentation discrepancy without editing source. MoDAModel adds the coefficient once to mean per-layer balance losses.

## Frozen fixture specification

Use deterministic toy tensors and seeded module initialization, never model outputs or real texts. The main fixture dimensions are batch1, sequence length5, model width16, query heads4, KV heads2, head dimension4 and two preceding depth entries. MoE uses4 routed experts, top2, one shared expert and expert hidden width8. Each MoDA test resets seed7101; each MoE test resets seed7201 so running a test in isolation does not change its inputs. A separate low-width reader fixture uses width16, one query/KV head and head dimension4, verifying that the actual projection implementation supports a smaller attention inner width; source config prose alone is insufficient evidence. Any additional seeds, dimensions or hand-set gate matrices must appear explicitly in the frozen test inventory before execution.

The input arrays and source-generated RoPE tables are part of the deterministic fixture recipe. For MoDA double-precision checks, convert the source's FP32 RoPE tables to FP64 and use those exact values on both sides; this is not a claim of freshly computed FP64 trigonometry. Keep dropout disabled. Do not normalize features or repair outputs after observing errors.

Two numeric acceptance classes are fixed before execution:

- MoDA FP64 forward and vector-Jacobian comparisons: elementwise abs(actual-reference) <= 1e-10 + 1e-9*abs(reference).
- MoE FP32 forward and vector-Jacobian comparisons, including the source's explicit FP32 gate behavior: elementwise abs(actual-reference) <= 2e-6 + 2e-5*abs(reference).

Pure attention and write-projection comparisons use the first class. End-to-end source block/model perturbation checks that pass through the explicitly FP32 gate use the second, mixed-path class even when the surrounding module is double. Changing future tokens can alter expert dispatch batch shapes and floating-point reduction paths, so causal perturbation checks use the applicable frozen numeric bound; bitwise comparison is reserved for identical-argument repeat and reload controls. This distinction is frozen before any numerical execution, not adjusted after a result.

Require finite operands/results before applying either bound. Record maximum absolute differences and the precise assertion for each comparison; a small maximum by itself does not replace the elementwise rule. Exact integer routing, shape, cache immutability, explicitly deterministic repetition and state-dict reload checks use exact comparison. Preserve signed-zero distinctions wherever bitwise equality is required. These are fixture acceptance bounds, not universal error bounds or relaxed historical thresholds. Never widen them after seeing a failure.

Independently construct a per-batch/per-query-head/per-token reference: directly project Q/K/V with the frozen parameter tensors; apply the same fixed positional transforms; enumerate only sequence positions <= the query position; append only past-depth entries at that same position; compute one dot-product softmax over this complete allowed set; sum values and project output. 2. Compare the L=0 source path with the explicit causal reference, and the L=2 source path with the combined sequence/depth reference. Include the GQA mapping query_head//group and confirm tensor layouts. A sum of separately normalized sequence and depth attentions is not an acceptable reference.
3. Compare vector-Jacobian products for inputs, the Q/K/V/output parameters and supplied depth K/V tensors using the same fixed scalar probe. The reference graph must be constructed independently. Require finite gradients and exercise nonzero depth-history participation. A shared upstream primitive is allowed; reusing the source's full attention expression is not independent validation.
4. Causality: at fixed full length perturb future sequence tokens and future positions of depth-cache tensors; require earlier outputs unchanged within the stated numeric bound and confirm the perturbation actually changes at least one future output. No data from a future token or current/future depth may be inserted into an allowed reference set.
5. Check explicit cache arguments are not mutated, no cross-call history leaks, correct empty-history behavior after a history-bearing call, deterministic repeat with identical arguments, and state-dict roundtrip into a new module instance. Save and compare state and repeated output bytes for the exact-repeat/reload cases.
6. If a source block or write-projection control is included, verify depth writes originate from the full preceding block output, key RoPE is applied once and values are not rotated. Treat this as interface accounting, not a combined mechanism quality experiment.
7. Check the registered low-width reader against the independent output/gradient reference. A zero-output-projection fixture may test an external residual y+attention(y) starting identically to y; it must not claim source MoDABlock itself is identity, because its post-normalization remains active.
