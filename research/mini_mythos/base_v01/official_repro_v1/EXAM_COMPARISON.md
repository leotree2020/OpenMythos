# 官方 CORE 与我们的十二条续写：考卷差在哪里

这两种考试测量不同能力。官方题库回答“在标准题目中能否选对或补对答案”；我们的续写检查回答“能否连续写出一段少重复、局部连贯的文本”。任何一边通过，都不能自动替另一边通过。

| 比较项 | 官方 CORE | 我们此前的 CPU-INFERENCE-V1 |
|---|---|---|
| 题目来源 | 官方代码下载的固定评测 bundle，22任务 | 手工冻结的12条开发 prompt，已被研究者查看 |
| 完整规模 | 每seed91037题次，三seed273111题次；HellaSwag分别0/10-shot | 12道不同题，每道64新token；重复/重载用于工程一致性，不增加独立试题数 |
| 考什么 | 常识、知识、阅读、指代、符号/算法等题目的答案评分 | 事实开头、故事、操作说明、代码、求职信、数列等自由续写 |
| 给不给示例 | 按题型0、3或10个few-shot例子 | 不给few-shot例子 |
| 选择题 | 把各候选答案放进输入，比较答案区间平均负对数似然，选最小 | 没有候选答案 |
| 填空题 | 使用正确前文的teacher-forced预测，答案每个token均须argmax匹配 | 每一步把模型刚刚生成的字接回输入，错误/重复可能继续累积 |
| 起始标记 | 原始代码补BOS；本次官方tokenizer包装器未定义特殊ID，因此原码回退BOS1/PAD0 | 旧12prompt未添加BOS，原tokenizer JSON直接编码 |
| 递归与精度 | 权重配置深度8；官方CPU路径实际FP32，无CPU autocast；本次不强制attention backend | 深度8、FP32、固定MATH attention |
| 随机性 | 三seed明确控制few-shot；官方代码没有给torch h0设固定种子 | 每prompt固定model seed731000+ID |
| cache/解码 | CORE不调用generate，不用KV cache或采样 | 旧评测greedy、无cache、完整前缀重新计算 |
| 合格/得分 | 每题对错→任务准确率→扣除随机猜测基线并中心化→22任务等权平均 | 自动重复/长度/解码规则 AND AI辅助连贯性，要求至少9/12共同通过 |
| 是否测长文本重复 | 没有我们的四元token重复门槛 | 同一4-gram达到3次即被自动筛掉 |
| 是否保证聊天/生产可用 | 不保证 | 12题小样本也不能代表生产质量，失败只针对这组固定测试 |

官方 CORE 的中心化公式是 `(accuracy - chance)/(1 - chance)`。例如四选一全靠猜，原始正确率25%对应中心化0；不是“25分能力”。论文140M/T8的14.04±0.20为CORE百分制平均±标准差，不是原始正确率14.04%，也不是允许我们本次结果落入的硬性成功区间。

一个真实例子：我们的“法国首都是……”续写开头已经答出 Paris，但后半段反复重复且包含错误断言。短答案评分可以关注答对的部分，我们的长续写筛选则会因后半段拒绝。因此旧结果不能简化成“模型什么都不会”或“官方没有意义”。它仍然表明旧解码条件下的连续文本有明显问题。

旧结果保持不变：工程加载/前向/重载一致性PASS；固定续写自动规则0/12，AI辅助局部连贯7/12，共同通过0/12，门槛9/12，质量screen FAIL。后来受控采样在第一步被我们的概率总质量1e-6门槛停止，未生成任何采样token；那个检查不是官方CORE的一部分，不应拿它判官方考试失败。

本次校准使用原始官方CLI的max_per_task=12，全部22任务与三seed，共792题次。此选项也把few-shot示例池缩小到12条，不是只缩小考题数。因此校准成绩不能直接与14.04比较，不能当作官方全量成绩。全部题库和评分代码均未改。

官方CPU路径与论文GPU/BF16条件的差异、公开权重SHA与论文表格之间缺少逐项映射、未固定的torch h0、跨版本依赖和有限样本均须保留。审计只从已保存得分/答案token重算决策和汇总，不假称再次独立计算了模型logits。
