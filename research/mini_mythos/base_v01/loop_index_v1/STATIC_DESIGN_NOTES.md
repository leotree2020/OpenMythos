## Accepted design

Use96 source-style sin/cos coordinates with theta10000, multiplied by one shared zero-initialized96-vector. Compare to a shared96-vector multiplying constant ones, and native F32. Both trained arms have exactly96 useful trainable parameters. This replaces the initially discussed32x768 learned depth table and768 shared bias, removing that proposal's32-fold capacity mismatch. No learned table or LoRA is part of the final design.

The source computes fixed sine/cosine additions rather than rotary rotation. Its first dim//8 channels become96 at width768. It injects before its own recurrent normalization, whereas this native Parcae experiment injects after native adapter and before the first core block. This is a documented inspired adaptation, not byte-for-byte reproduction of the OpenMythos model. The added zero gain is necessary to start from the pretrained function and differs from unconditional source injection.

All32 iterations consume the shared gain through different fixed features. A fixed32 table of immutable feature values may be precomputed, but trainable state remains only96 values. The first48 sine features vanish at t=0; later iterations generally supply gradients to these coordinates. Gain starts identically for both training seeds; h0 seeds supply the registered training randomness. No meaningless random-initialization claim should appear.

## Risks and required implementation review

1. Ordinary floating-point addition at zero may change signed-zero bit patterns. Do not bypass the addition when gain is zero, because a shortcut can sever the only trainable gradient or conceal the operational difference. Require actual native-output bitwise identity using the unchanged comparator. A mismatch stops execution.
2. Do not require each of96 coordinates to have a nonzero gradient on every step. Cancellations and small feature amplitudes are possible. Require finite present gain gradient and nonzero vector norm/update and report coordinate coverage. Retain all32 independently computed delta tensors per forward; every step requires32 present finite delta gradients. The actual gain-gradient contribution at depth t is delta_t.grad[:96] * feature[t] (source code for C, ones for S); do not take the full padded768-dimensional gradient norm. Every arm/seed requires all32 depths to have a nonzero contribution norm at least once across its32 training steps. The32 contributions sum mathematically to gain.grad; verify the decomposition with a declared tolerance in a development fixture. This controls graph participation without demanding that every coordinate or every depth be nonzero on every step. A zero sine coordinate at t=0 is expected.
3. Only a native adapter forward hook may add the code. Exactly32 calls must be observed, including in training. Counters must reset on each call, saved backward graphs must not depend on mutable counter state, and finally cleanup must restore prior model instrumentation and h0 observer state. No activation checkpoint replay is allowed.
4. Do not detach the gain product, use .item() on it in the forward computation, mutate native output in place, or feed labels to the code. Feature construction and evidence inspection must not consume paired h0 RNG.
5. Feature amplitude/conditioning differs between source sinusoids and constant ones. Equal parameter count does not isolate every optimization explanation. No RMS normalization is added; interpretation remains about the frozen recipe. Matched code/shared controls address the old capacity concern without claiming an abstract universal causal theorem.
6. All16 validation articles were used by the prior LoRA pilot. Label the result development evidence and do not call it fresh generalization. Do not choose LR, gain initialization, channel width, frequency base or training duration after scores are seen.
7. Separate engineering acceptance from scientific practical screens. C beating F but not S is adaptation evidence without a passing depth-specific advantage. A valid negative screen is retained; it does not justify immediate tuning or a formal run retry.
8. Preserve originals:63 base state entries, read-only pinned upstream, official weights, old results, controller threshold, B1/A5 state. The new gain checkpoints and raw logits belong to the new isolated evidence tree.
9. The raw logit allocation is exactly1,342,177,280 bytes; with64MiB records and256MiB reserve the admission requirement is1,677,721,600 bytes. Avoid duplicate raw archives and unbudgeted temporary packs. Storage status is an engineering guard, never a scientific result.
10. Verify launcher/branch/run-path interfaces using the intended invocation path before freeze. Prior execution history includes branch-binding failures, so a helper test of the numerical function alone is insufficient.
