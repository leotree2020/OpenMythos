## Reviewed basis and scientific choice

Pinned OpenMythos MoDAAttention actually implements a joint softmax over causal sequence positions and previous-depth same-position keys. The completed source-math phase at5d9df2733f2b04cab9515db8c51c6b37a7443bda tested its reference equations, gradients, low-width reader, causal isolation, writes and reload separately from language quality. Native Parcae source at69284c13746e849104f738d6d1a347b1f457df76 confirms adapter-before-two-core-block ordering and that core_block_forward returns the second core output.

The proposed integration retains native attention/FFNs and adds a low-width actual-source residual reader. It is not a remapping of pretrained weights into the full OpenMythos architecture. Both trained arms have12288 output-projection parameters and identical frozen random feature maps per seed, removing a trainable-capacity difference from the history comparison. Both compute32 writes; only the history arm consumes old writes. More history attention work remains, so equal parameters are not equal computation.

The full-core output used for history is an explicit integration point, not a claim of equivalence to the post-normalized output in the full source MoDABlock. The final write is unused by design. Source RoPE16 is auxiliary branch state and never changes the native buffer or A5 criterion.

## Important implementation conditions

1. Construction order and RNG isolation are exact: source attention, zero output weight, K writer, V writer, source RoPE, inside a CPU RNG fork seeded4101/4202. Both trained arms must match feature bytes and preserve external RNG. Only output projection trains; native and61440 frozen feature parameters never gain gradients or change bytes.
2. Hook ordering must prevent current-depth leakage. A read at depth t sees exactly t completed prior writes; write t occurs after the second native core block. Every forward starts fresh lists/counters and finally restores all hooks/observers. Native initialization and32-step BPTT stay intact.
3. Zero projection suppresses gradients into attention features/history on the first step; this is expected. The final history write and all sequence-control writes are unused. Distinguish these cases from missing branch-output gradients or detached consumed history. Report per-depth coverage without claiming useful computation from mere gradient participation.
4. The96-gain loop mechanism, LoRA and ACT are absent. Feature learning capacity differs substantially from the earlier loop pilot, so do not compare its gain magnitude as a clean ranking of architectures. The reused16-article validation set is development evidence only.
5. The independent per-case auditor must see every complete new matrix before temporary deletion. Successful worker execution or saved NLL alone is insufficient. Cases, targets, h0/RNG, hashes, exact sizes, per-token NLL and predictions must agree. Source matrix dtype must stay FP32 and all score arithmetic must be documented FP64.
6. The old32 F32 files provide a hash-bound baseline bridge, not permission to skip new native predictions. Observer schema names can differ; actual h0/RNG, targets and logit bytes must match. Preserve old files and never rewrite evidence to make a bridge succeed.
7. Only one newly created temporary row may be removed after its independent PASS and a fresh path/hash/size check. Failed rows, old files and four designated sentinel rows are retained. Distinguish original raw availability from compact summaries in every final report.
8. For124 cases, later auditors cannot recompute full logsumexp or argmax from the retained compact records. Their support is the independently audited execution and hash-bound receipt; future full reproduction would be separate. Do not claim earlier stages' retrospective full-logit audit coverage.
9. Per-token top2 margin is descriptive, not an added acceptance threshold. Stable tie-breaking must be explicit, and chunk sums/squares do not reconstruct or prove the distribution by themselves.
10. The initial16MiB artifact proposal was revised to32MiB before formal freeze/execution because complete packaging estimates were not yet established and the smaller allocation was too tight. Total disk admission is now328MiB, including the unchanged256MiB reserve. This is a pre-execution resource correction; no scientific threshold or measured-model result was involved. The32MiB allocation still requires a concrete packing proof covering binary adapter/optimizer state, all row/step reports, verbatim process/check logs, protected-file inventories/old manifests, duplicate public copies and Git growth. An overflow blocks this protocol before real-model calls; do not trim or silently enlarge it after scores exist.

## Claims this experiment can and cannot support

If H passes both H/F and H/S screens in both seeds, this supports the local history-reader recipe on this development benchmark, with added attention cost. H/F alone supports adaptation without establishing additional-history value. A negative result does not reject every MoDA design. None of these screens establishes fresh generalization, statistical significance, generated-text usefulness, equal-compute superiority or interaction with other mechanisms.

Training/evaluation and live-audit/I/O timing must be separated. The per-row subprocess design adds overhead and is not a production inference benchmark. A compact storage scheme does not justify reducing score positions, precision or case count on the fly.
