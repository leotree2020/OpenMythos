# MYTHOS-ADAPTIVE-DEPTH-DEV-V1

Purpose: develop the first isolated computation-control mechanism on the native Parcae interface. The user's long-term target is a reproducible open model approaching Claude Mythos capabilities. This stage establishes implementation correctness, not capability reproduction or quality improvement.

Base: OpenMythos checkpoint c63b829a752ac57d22addfe17ff53ecbcb58e8a0, branch mythos-depth-16-32-cpu-v1. New branch mythos-adaptive-depth-dev-v1; all additions under research/mini_mythos/base_v01/adaptive_depth_v1/. Upstream Parcae remains read-only at 69284c13746e849104f738d6d1a347b1f457df76. Original B1 A5 and the rejected old source-unit interpretation are unchanged. No B1 rerun, B2, D2-A, GPU, dependency installation, trained weights, external model API or PR #24 operation.

Environment: local Windows CPU development is permitted for this new stage, using the already installed Python/Torch, exact versions recorded with results. Use -I -B, CPU FP32 model tensors, FP64 policy calculation, eval/no_grad, deterministic algorithms and one intra-op/inter-op thread; record actual settings. This is not the Codespace's official 140M execution environment. No claim of cross-machine numerical identity. Upstream tracked bytes and Git status must remain unchanged.

Input: synthetic tensors and, if installed dependencies allow, an untrained tiny model constructed from the pinned native Parcae source. Never load real 140M weights, original raw result rows, or unseen evaluation articles in this stage. Fixture outcomes cannot establish language quality.

Candidate policy, fixed before model-quality evaluation: for one supplied prefix (batch size one), initialize h0 and prelude once; continue the same native recurrent state to depth 8, read out, continue to 16, read out. Compute TV = 0.5 * sum(abs(softmax(logits8.double()) - softmax(logits16.double()))) over the vocabulary at the final prefix position only. Stop at depth 16 if TV <= 0.01; otherwise continue that same recurrent state to 32 and read out. This policy cannot exit at 8. The value 0.01 is an arbitrary engineering starting point, not a validated quality threshold, and will not be tuned on the existing 32-article results. Stable predictions can still be wrong. Nonfinite values cause failure, never fallback.

The policy is a nonlearned early-exit controller inspired by adaptive computation. It is not the learned ACT module from OpenMythos, a transcription of Claude Mythos, or a new trained model. Preserve native state updates. Do not mix states, install random adapters, change injection/attention/RoPE, or replace buffers.

Interface boundary: CPU inference-only, batch one, no padding, masks, position override, KV cache, labels or optimizer. Each invocation predicts only the next token after its entire supplied prefix. Never use a whole teacher-forced window's last-position decision to select logits for earlier positions. Unsupported configurations must fail explicitly. Save and restore any temporary native input-ID bookkeeping, including on exceptions. Coda/readout must operate on an isolated copy and cannot feed back into the recurrent state. Fixed-depth control supports 8/16/32 with native operation order. Native core ignores total_steps in the pinned implementation; do not generalize this assumption to other source versions.

Expected engineering acceptance:

1. Policy numerical semantics match an independent scalar reference; identical distributions have zero TV; equal finite logit shifts preserve probabilities within a declared numerical tolerance; threshold equality exits at 16. Reject shape/dtype/nonfinite/invalid inputs.
2. Fixed-depth path and resumed native path give bitwise equal final logits at 8/16/32 under the same h0/RNG on the same process/hardware. Compare dtype/shape and byte patterns, not torch.equal alone. No relaxed tolerance for this identity check.
3. Intermediate readouts do not mutate recurrence state or consume RNG. Prelude/h0 each execute once. State_dict bytes and caller input bytes remain unchanged. Restore temporary model attributes on normal exit and injected exceptions.
4. A forced synthetic stable fixture exits at 16 and actually makes no depth 17-32 core calls. An unstable fixture reaches exactly 32. No extra core calls or restarts. The optional native tiny model must match independently executed native forward at its selected depth.
5. Count every prelude/core/coda/projection/head call and policy evaluation. For native 2/2/2 blocks: fixed16 uses 36 block calls; adaptive16 uses 38 (two readouts); fixed32 uses 68; adaptive32 uses 72 (three readouts). Counts exclude projection/head/policy, which must be separately reported. These are not FLOP or latency savings. No per-token-mask savings claim.
6. CPU, eval/no_grad and finite-tensor guards; reject batch>1, training, unsupported cache/config/device/dtype paths. No hidden target labels accepted by controller API. Test isolation across calls and causal-prefix semantics on native tiny inputs when available.
7. Each test/check records Purpose, Environment, Input, Expected, Actual, Status. A command exit code is necessary but not the sole acceptance criterion. Preserve stdout/stderr, test counts, failing assertions and exceptions. Skipped or unavailable native checks are NOT TESTED/BLOCKED, never PASS.

Development fixes may be made before the final source freeze, with failures retained and explained. Freeze source hashes before the final acceptance invocation. If final frozen acceptance FAIL/BLOCKED, save evidence and stop; no unrecorded retries. The final checkpoint distinguishes synthetic tests, native tiny validation, 140M validation, scientific performance, and trained-model reproducibility.

Actual: pending. Current results and exact dependency environment are recorded in DEVELOPMENT_RESULTS.json and CHECKPOINT.md after execution. Formal140M validation, performance comparison, training/recovery and Claude Mythos parity all remain NOT TESTED. Formal Oracle remains BLOCKED/NOT_READY; FORMAL_ACCEPTANCE_READY=False.

Existing historical data are development evidence only. Do not select a policy using test labels.
