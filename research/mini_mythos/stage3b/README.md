# Stage 3b:深度 LoRA(按循环轮次调制)单项实验(方案草案,待批准)

规则见根目录 `CLAUDE.md`(宪章 v2.0)。前置:阶段 3a CLOSED(2026-11-09,FAIL)。机制背景见 `../MECHANISMS.md` 第 4 条。参考实现:`open_mythos/main.py` 的 `LoRAAdapter`。代码在负责人批准本方案后再写。

## 目的

检验一件事:让循环核心的共享权重**知道现在是第几轮**,从而每一轮做不同的事,是否比“每轮都一样”的普通 LoRA 更好。比较时两者参数几乎相同,用同样的数据和同样的调参次数。

**大白话**:Parcae 每一轮用的是同一套零件,所以第 1 轮和第 8 轮只能做同样的动作。深度 LoRA 给每一轮发一个小旋钮,让同一套零件在不同轮次里稍微换个用法,比如前几轮粗读、后几轮细抠。对照组是一模一样的零件,只是没有这个旋钮。

## 机制:D-LoRA(深度 LoRA 的 Parcae 版)

**接在哪里**:循环核心的 2 层。每个线性层都加 LoRA:attention 的 q、k、v、proj,MLP 的 fc、proj,以及 value-embedding 门控。

**公式**:`y = W x + 2 · B · (c_t ⊙ A x)`。
- `A`、`B` 在 8 轮之间共享,和普通 LoRA 一样;
- `c_t` 是第 t 轮自己的缩放向量,长度等于 rank;
- 系数 2 就是 alpha/rank。

和参考实现的关系:参考的 `delta = (down(x) * scale[t]) @ B` 只有一个适配器,加在整个块的输出上。这里把同样的形式放到每个线性层上,好让对照只差“每轮缩放”这一处。

**初始化**:`B = 0`、`c_t = 1`。这时 D-LoRA 与普通 LoRA **完全相同**,也与原生 Parcae 完全相同。训练中唯一能产生差别的就是 `c_t`。

**轮数从哪来**:用钩子数核心块在一次前向里被调用的次数,不改上游代码。超过训练轮数时(只在深度 16 的报告项里出现),沿用第 8 轮的缩放,与参考实现的截断做法一致。

**参数量**(rank 16):
- 共享 A/B:2 层 × 27,686 × 16 = 442,976;
- 每轮缩放:13 个线性层 × 8 轮 × 16 = 1,664;
- 合计 **444,640**。

- 训练设置相同(bf16、序列长 1024、全局批 32、8 轮且后 4 轮反传、AdamW、预热加余弦、梯度裁剪 1.0)。

## 数据:改用“保留余量”的打包

3a 发现,上游式打包把放不进当前行的文档截断后丢掉余量,只用上了 48% 的语料。本阶段改为:**截断后,余量作为一篇新文档放回缓冲区**。
- 预计每次训练约 5000 万 token,每次约 1500 步,语料用满一遍。
- 代价:有些训练行从文档中间开始,而 Parcae 预训练时每行都从文档开头开始。模型不用 BOS,所以影响应该很小;而且这对两组完全相同。
- 评测不受影响:评测窗口仍从文档开头取。
- 改动放在新的打包函数里,阶段 2 和 3a 的代码与结果不变。

## 评估与通过标准(沿用 3a 的冻结模板,看结果前冻结)

**评估**:FP32,深度 8,不加 BOS,2 个副本,初始状态在 CPU 上生成。开发集每领域 100 个窗口,测试集每领域 200 个窗口。

**主指标**:测试集上逐窗口配对的 `D − C`,按领域报告均值和 95% bootstrap CI。

**第一步,开发集关口**:两个种子下,D 在 3 个异领域(books、c4、wikitext)上的平均开发集 NLL 都要低于 C。不满足就判 FAIL,测试集不用。

**第二步,测试集**。冻结两个候选:D 和 C 各取选中学习率下 seed 0 的模型,各评一次,记入 `stage1/TEST_LOG.md`。这是测试集第二次被用于机制比较,报告中注明。PASS 需要同时满足:
1. 3 个异领域里至少 2 个满足:`D − C` ≤ −0.003,且 CI 上界 < 0;
2. 3 个异领域的平均 `D − C` ≤ −0.003;
3. 没有领域明显变差,即 CI 下界 > 0 且均值 > +0.003 的领域一个都没有;
4. 开发集上,两个种子的 `D − C`(异领域平均)都为负,且都大于训练噪声下限。噪声下限的定义同 3a。

**只报告、不作门槛的项目**:
- `D − N`;
- 训练后各轮缩放 `c_t` 彼此差多少,即模型是否真的“按轮次区分”;
- 深度 16 时的开发集分数。这一项回答“机制是否让多跑几轮更有用”。
