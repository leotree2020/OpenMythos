# 想法说明:热力学式的逐级维度扩张(草案 v0.1,2026-11-09)

状态:**想法阶段**,还不是实验方案。负责人确认方向后,再按宪章 v2.0 写成一页实验方案(冻结标准后再跑)。提出人:项目负责人;起草:Claude Code。

## 1. 一句话

不靠“几十万亿 token 的规模”硬堆,而是让模型的表示**像热扩散一样逐级展开**:先在极低的维度里学到最重要的结构(点),再一步步加维度(线 → 面 → 高维空间),每次加维时用“温度”(噪声)从高到低退火,让新维度自己找到有用的方向。

## 2. 我们要检验的,以及不打算声称的

**要检验的**:在**同样的训练算力和同样的数据**下,逐级扩张训练出的模型,是否比“一开始就用全部维度”训练的模型更好,或者达到同样好所需的算力更少。

**不声称的**:这个方法**不能免去对数据的需求**。模型的知识只能来自数据、老师模型(蒸馏)或模拟器;热力学原理不会凭空产生信息(信息论和热力学第二定律都排除了这一点)。我们期望的是**效率**提升,前人类似方法通常是几成到一两倍,不是几千倍。

## 3. 名词对应(要先说清楚,不然没法检验)

| 想法里的词 | 在模型里对应什么(候选) |
|---|---|
| 点 / 线 / 面 / 维度空间 | 表示的**秩**,即有效维度:1 → 2 → 4 → … → r |
| 扩散、展开 | 按时间表**增加可训练的维度**,新维度从 0 开始,保证加维瞬间模型输出不变 |
| 温度 | 加到新维度上的**噪声强度**,随训练逐步降低(退火) |
| 能量 | 训练损失(NLL) |
| 平衡 / 冷却 | 某一阶段的损失不再下降 → 进入下一阶段加维 |

## 4. 理论与前人工作依据

1. **学习本来就是“从低维到高维”**:
   - 深度线性网络的梯度下降,会按重要性**一个方向一个方向**地学(Saxe 等,2014);
   - 更一般的网络里,也观察到“从一个鞍点跳到下一个鞍点”、秩逐级增长的现象(Jacot 等,2021,saddle-to-saddle)。
   - 这是“点 → 线 → 面”最直接的理论支撑。我们的想法相当于**把这个自然过程显式地安排出来**。
2. **热力学 → 生成与优化**:
   - 扩散模型源自非平衡热力学(Sohl-Dickstein 等,2015;Song 等,2021);
   - 带噪声的梯度下降,可以看作在损失“能量地形”上的朗之万动力学(Welling & Teh,2011);
   - 模拟退火:先高温广泛探索,再降温收敛。
3. **逐级长大的模型**:
   - 渐进式增长的 GAN(Karras 等,2018);
   - 保持函数不变地把小网络扩成大网络(Net2Net,Chen 等,2016);
   - 渐进堆叠(Gong 等,2019);
   - 学习式增长(LiGO,Wang 等,2023)。
   - 这些工作说明“先小后大”能省算力,也说明省的幅度有限。
4. **嵌套维度**:Matryoshka 表示学习(Kusupati 等,2022),前 k 维单独就可用。
5. **物理里的粗粒化**:重整化群与深度网络的对应(Mehta & Schwab,2014)。
6. **和我们的 Parcae 的联系**:循环模型每多跑一轮,就把表示打磨一次;扩散模型每一步也是去噪一次。两者都是“迭代精炼”。

## 5. 可检验的假设

- **H1(主假设)**:同样的数据和训练 token 数下,把新增参数的秩按“1 → 2 → 4 → … → r”逐级放开(每级都从 0 开始),最终开发集 NLL 低于一开始就放开到秩 r 的对照。
- **H2(热力学部分)**:每次加维时,给新维度加一段从高到低退火的噪声,比不加噪声更好。
- **H0(负结果也有价值)**:如果 H1、H2 都不成立,说明“显式安排逐级扩张”对这个规模没有额外好处。

## 6. 最小实验(两个选项)

**选项 B(推荐先做,符合宪章,很便宜)**:在 Parcae-140M 上做“秩的逐级扩张”。
- 底座 Parcae-140M。额外零件用阶段 3 现成的 LoRA r28,和 3a 的对照一模一样。
- **扩张组**:秩分阶段放开 1 → 2 → 4 → 8 → 16 → 28,每段训练量相同;新放开的维度从 0 开始;H2 再加一组退火噪声。
- **对照组**:秩 28 从头到尾全部放开。
- **同预算**:同样的参数总数、token 数、学习率搜索次数和种子数。评估、去污染、测试集规则全部沿用阶段 3。
- **预计**:每组约 5000 万 token。在 4090 上总共约 2–3 小时,约 $2。
- **局限**:冻结底座上 LoRA 本身收益就很小(阶段 2、3a)。所以这个选项主要检验“逐级扩张这个训练过程”,不太可能带来大的分数提升。

**选项 A(更直接,但要宪章例外)**:从随机初始化训练一个小语言模型(约 1000 万–3000 万参数),比较“宽度或秩逐级扩张”和“直接训练全尺寸”。
- 这最直接地检验 H1、H2。
- 但宪章第 1 条写明“不再从随机初始化训练自己的权重”,所以需要负责人批准把它作为**独立的研究支线**,不算 Mythos 主线。
- 约 2 亿 token,2–4 组,预计 $3–8。

**通过标准(草案,写方案时再冻结)**:与对照相比,开发集上 4 个领域的平均 NLL 改善,要超过训练噪声下限的 2 倍;两个种子方向一致;再在测试集上确认。另外报告“达到同样 NLL 所需的 token 数”,这是更直接的效率指标。

## 7. 风险

- **定义漂移**:如果不把“维度”和“温度”说死,结果怎么解释都行。第 3 节的对应要在方案里固定下来。
- **效果可能很小**:前人类似方法的收益是几成;在我们的规模上,甚至可能测不出来。
- **和 3b 混在一起**:等 3b 结束后再开始,避免两个实验共用 Pod 或分支。
