**原失败项 `judgment_without_ledger_recovered`：通过**。过程如下：
1. 中断前启动器已记账 1 个判定。
2. 测试删掉它的哈希，然后续跑。
3. 续跑时，4 个"有文件、无账本"的判定（被删哈希的那 1 个，加上中断时刚写出、尚未记账的 3 个）都先经过身份和 test2 核对，再记为已恢复，没有重做。
4. 续跑后重新启动的 11 个判定，在续跑前都没有文件。
5. 15 个判定文件齐全，并且全部记账。

**新发现的启动器缺口，验证结果**：
- `judgment_without_ledger_invalid`：先放置一个属于别的种子、test2 哈希也不符的遗留判定文件，再启动阶段 4。
- 启动器以退出码 3 停止（"not a complete judgment of this run on this test2 … never redone"），这个运行的判定作业一次也没有启动。
- 再结合第 3 节的函数级检查（身份与 test2 哈希分别不符时都会拒绝），补丁 B 的核对被覆盖到了：在启动器层面，作为一次完整性失败；在函数层面，逐项核对。
