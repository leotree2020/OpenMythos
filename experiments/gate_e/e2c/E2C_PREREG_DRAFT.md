## 0. 背景、范围与原则

### 0.1 E1 给出的出发点（探索性观察，不是已证实的结论）

E1（`experiments/gate_e/E1_REPORT.md`）的 K=2 两变量查值任务中：

1. **线性可读性下降早于选根形成**：10 次运行中，数字位置变量字母的线性可读性（P2，线性·标准化探针）持续下降（t_P2lin），都在第 50 或 75 步，早于选根形成 t_R（第 150 步）。两组都是 5/5 一致。
2. **字母敏感性仍在**：所有运行中，t_M3 都未发生，数字位置状态仍随字母变化（s = 1.000）。K=2 的 MLP 可读性也没有持续下降（t_P2mlp 未发生，10/10）。
3. **选根之后的分化**：所有 K=2 运行都先进入选根阶段，之后出现分化：
   - Transformer 5/5 学会；
   - OpenMythos 2/5 学会，另外 3 个停在与查询无关的选根策略上（test_heldout 准确率约 0.50，查询不敏感率 0.985–1.000）。
4. **第 12000 步的可读性**（描述）：
   - 学会的 7 次运行，A_lin 都高于 t_P2lin 门槛；
   - 未学会的 3 次，都低于门槛。

E1 审核结论：
- 时间先后不能证明可读性下降导致了失败；
- "简单探针读不出来"不等于"信息被删除"；
- 需要研究的是：为什么部分训练轨迹能离开选根阶段，另一些却停在那里。

### 0.2 本实验要回答的问题

在训练中加入一个辅助任务，让数字位置的字母信息保持线性可读，是否足以让模型更可能、更早地离开选根平台，学会按查询取值？

- E2-c 检验的是**充分性**型干预："保持可读"是否改善学习。
- 它不检验必要性："失去可读性是否必然导致失败"不在本实验范围内。

### 0.3 原则

- **先复现再改进**：
  - 任何干预条件运行之前，先在当前环境中逐位复现 E1 的训练轨迹和诊断数值（第 6 节 R1–R3）；
  - 复现不通过，就停止，不进入干预。
- **上游优先**：
  - 训练数据流、初始化、优化器、学习率计划、batch、步数、留出规则都与 E1 完全相同；
  - 只增加辅助损失，不修改模型架构，不修改 `open_mythos/` 和任何已归档代码。
  - E2-c 的新代码只放在 `experiments/gate_e/e2c/`，以只读方式导入 E1 模块。
- **每阶段结束后停止**：每个阶段结束后停止并等待审核，不自动推进（第 10 节）。
- **不比较架构**：两组分别报告，不据此判断架构优劣。

## 1. 假设、因果机制与可证伪条件

### 1.1 假设的因果链

要按查询取值，读出位置（`?`，位置 10）必须找到"变量字母与查询字母相同"的那条语句，再取出它的数字。一种可能的实现方式是：

1. **绑定**：数字位置（2、6）的状态中，含有可被线性读取的"本语句的变量字母"；
2. **匹配**：读出位置的注意力用查询字母与这些"字母键"做匹配，从而选中正确的数字；
3. **逃离平台**：匹配一旦形成，梯度就开始支持按查询取值，模型离开"在两个根数字里选一个"的平台。

**假设 H**：训练早期，数字位置字母信息的线性可读性下降，使第 2 步缺少可用的"键"，于是选根平台更难离开。所以，人为保持这种线性可读性，应提高学会的比例或加快学会。

**竞争解释**（本设计需要能区分）：
- **A1 伴随现象**：可读性下降只是伴随现象。学会与否取决于别的因素，例如梯度对称性的打破（t_G），或注意力路径的形成。那么保持可读性不会改善学习。
- **A2 一般辅助监督效应**：任何额外的辅助监督，都可能通过增加梯度、正则化或改变优化器状态而影响学习，与绑定内容无关。这由非绑定对照 C2 检验。
- **A3 反方向**：E1 中学会的运行最后 A_lin 回到门槛以上，可能是"学会了才需要可读"，即学会导致可读，而不是可读导致学会。保持可读如果无效，与 A3 一致，但不能证明 A3。

### 1.2 两类结果必须分开

| 类别 | 问题 | 指标 | 作用 |
|---|---|---|---|
| **操纵检验 H-M**：保持线性可读性 | 干预是否真的让数字位置的字母保持线性可读？ | 独立探针的 A_lin(t)，以及 t_P2lin 是否发生（第 5.2 节） | 前提条件。操纵失败时，不能检验 H |
| **结果检验 H-Y**：提高任务学习 | 保持可读之后，是否更可能、更早学会按查询取值？ | 新的封存测试集上第 12000 步是否"学会"；开发集上的 t_L（第 5.1 节） | 主要结论 |

- 操纵成功本身不是"实验成功"。
- 学习改善如果没有伴随操纵成功，也不能归因于"保持可读"。

### 1.3 可证伪条件（以 OpenMythos 的确认性检验为准，见第 7 节）

- **支持 H，并且是绑定特异的**：操纵检验通过，C1 的学会率显著高于 C0，并且显著高于 C2。
- **否定 H（在本设定下）**：操纵检验通过，但 C1 对 C0 的学会率差异不显著，并且配对差的 95% 置信区间上限低于最小关注效应 Δ_min = 0.30。
  - 含义：保持线性可读，不足以使学会率提高 30 个百分点或更多。
- **只支持一般辅助效应**：C1 显著好于 C0，但与 C2 没有显著差异。此时不能归因于绑定内容（A2）。
- **不可判定**：
  - 操纵检验未通过；
  - 或者 C0 中未学会的种子少于 5 个，没有改善的空间；
  - 或者差异不显著、但置信区间上限 ≥ Δ_min。

## 2. 任务、模型与训练配方（与 E1 完全相同的部分）

- **任务**：K=2 直接查值，格式 `a=3;b=7;|b?` → `7`。由 `gen_gate_a/levels.py` 的 `_chains_prompt(rng, [1, 1])` 生成。字母在位置 0、4，数字在 2、6，查询字母在 9，读出位置在 10。
- **留出规则**：与 E1 相同。题面的无序语句集合作为键，sha256 对 10 取余为 0 的题面不进入训练。
  - 训练分布因此与 E1 完全相同，这是逐位复现 E1 的前提。
- **模型**：`build(arm, 2)`，不修改。
  - 两组：OpenMythos（T=4，ACT 读出，原生代码）和参数量匹配的 Transformer。
- **训练**：
  - AdamW，学习率 2e-3，按 `budget_a/schedule.extended_lr`（预热 100 步，余弦到第 3000 步，之后保持 2e-4）；
  - 权重衰减 0.1，batch 64，12000 步；
  - 任务损失只在答案位置计算；
  - 梯度裁剪 1.0，只对模型参数计算范数（与 E1 相同）。
- **初始化**：`torch.manual_seed(seed); build(arm, 2)`。
- **训练数据 RNG**：`random.Random(60000 + seed)`。同一种子下，两组、三个条件的题目序列逐题相同。

## 3. 三种条件

| 条件 | 训练损失 | 辅助标签 |
|---|---|---|
| **C0 原始训练** | L = L_task，与 E1 完全相同 | 无 |
| **C1 绑定辅助监督** | L = L_task + λ · L_bind | 每个数字位置的标签是本语句的变量字母（52 类）。标签由输入本身决定，不含查询或答案信息 |
| **C2 非绑定辅助监督** | L = L_task + α_t · L_rand | 每个数字位置的标签是与输入无关的随机字母（52 类，均匀）。来自独立的 `random.Random(80000 + seed)`，每步按固定顺序抽取，不消耗训练数据 RNG |

### 3.1 辅助头（C1、C2 相同）

- **形式**：
  - 每个监督记录点各有一个线性映射 d_model → 52；
  - 用独立的 `torch.Generator().manual_seed(90000 + seed)` 初始化，之后固定不训练（待审核决定 D1）。
  - 固定的头没有可学习参数：C1 与 C2 的额外参数相同（都是 0 个可训练参数），同一种子下两者的头权重逐位相同。
- **监督位置**：数字位置 2 和 6。
- **监督记录点**：与 E1 的 M2 记录点相同，但不含 `emb`（待审核决定 D3）：
  - OpenMythos：`e`、`h1`、`h2`、`h3`、`h4`、`h_out`、`coda_out`；
  - Transformer：`out0`、`out1`、`out2`。
- **损失**：交叉熵，对 batch、两个数字位置、全部监督记录点取平均。
- **获取隐藏状态**：用与 E1 诊断相同的记录点提取方式，在训练前向中保留梯度。不修改模型代码。
- **ACT**：OpenMythos 的循环状态，以训练前向实际计算出的值为准。实现阶段要核对每一轮的状态是否都被计算。
- **评测**：辅助头只在训练中使用，所有诊断和正式判定都不使用它。

### 3.2 控制额外梯度：C2 与 C1 按种子逐步配对（yoked）

问题：
- C1 的辅助任务能学会，L_bind 会下降，梯度随之减小；
- C2 的随机标签学不会，梯度不会减小；
- 如果 C2 用固定权重，它注入的额外梯度会越来越大于 C1。

所以按种子逐步匹配强度：

1. C1 每一步记录 r_t = ‖∂(λ L_bind)/∂H_t‖，其中 H_t 是该步所有被监督的隐藏状态，范数为 Frobenius 范数。
   - 这个量可以由辅助头直接算出，不需要额外反传过模型。
   - 整条记录存为运行文件，sha256 写入运行记录。
2. C2 在同一种子、同一步，取 α_t = r_t^(C1) / ‖∂L_rand/∂H_t‖，使注入到被监督状态上的误差信号范数与 C1 逐步相同。
   - α_t 的上限为 10λ。达到上限的步数比例要报告；它不是停止条件。
3. 因此，C1 与 C2 的差异只在信号的方向：
   - C1 指向"保持绑定可读"；
   - C2 是与输入无关的随机方向（期望上把辅助头的输出推向均匀分布）。
4. 参数层面的辅助梯度范数：在与 E1 相同的记录频率（前 1000 步每 10 步，之后每 100 步），额外反传一次辅助损失并记录 ‖∂L_aux/∂θ‖。
   - 用 `autograd.grad`，不累加到参数梯度，不影响训练轨迹。
   - 同时记录梯度裁剪生效的比例。三种条件都报告。

C2 依赖同一种子的 C1 记录，所以每个种子都按 C1 → C2 的顺序运行。C0 与两者无关。

### 3.3 λ 的选择（实现阶段，只用非正式种子，只看可读性）

- **候选值**：λ ∈ {0.03, 0.1, 0.3, 1.0}。
- **校准种子**：91、92、93，每组单独选择。
- **校准过程**：
  - C1 训练到第 3000 步，检查点为 0、25、50、75、100、150、200、300、500、1000、2000、3000；
  - 用 E1 的 `diag_fit` / `diag_eval` 计算独立探针的 A_lin(t)。
- **规则**：选最小的 λ，使 3 个校准种子在第 50–3000 步的每个检查点上都满足 A_lin(t) > 门槛（门槛定义见 5.2 节）。
- **只看可读性**：选择只依据可读性，不看任何任务学习指标。校准运行的学习指标照常记录并在审计日志中报告，但不参与选择。
- **都不满足时**：停止并报告（第 9 节 F4），不扩展候选范围，不改规则。

### 3.4 必须相同、或被记录的量

| 项目 | 控制方式 |
|---|---|
| 训练步数、batch、学习率计划、优化器、权重衰减 | 三种条件完全相同 |
| 训练题目序列 | 同一种子下逐题相同（Random(60000 + seed)） |
| 初始化 | 同一种子下逐位相同 |
| 监督量 | C1、C2 的辅助标签数相同：每步 64 题 × 2 个数字位置 × 记录点数；类别数相同（52） |
| 额外梯度 | C1 与 C2 在被监督状态上的误差信号范数逐步相同（3.2）；参数层面的范数和裁剪比例都记录 |
| 额外参数 | C1、C2 都是固定的头，0 个可训练参数；头权重同种子相同 |
| 计算量 | C1、C2 多出辅助头的前向和少量梯度计算（估计 +10%），更新次数不变。记录实际耗时，不作补偿 |

## 5. 指标

### 5.1 任务学习（结果检验 H-Y）

- **主要指标（每次运行）**：在新的封存测试集 `test2_heldout` 上，第 12000 步是否"学会"。
  - 门槛与 E1 第 5.3 节相同：准确率 ≥ 90%，换根双对率 ≥ 80%，换查询双对率 ≥ 80%。
- **关键次要指标**：t_L，即在 `dev2_heldout` 的训练日志上，第一个满足"准确率 ≥ 90% 且换查询双对率 ≥ 80%"、并且下一个记录点也满足的步数。
  - 记录频率与 E1 相同：前 1000 步每 25 步，之后每 250 步。
  - 与 E1 不同的是，E2-c 直接用全部日志点，而不只用检查点。到第 12000 步仍未发生，记为"未发生"。
- **其他次要指标**：
  - 第 12000 步 `test2_heldout` 上的准确率、换根双对率、换查询双对率、查询不敏感率；
  - 按 E1 第 5.3 节和 9.5 节的三个等级；
  - 在 `diag2_eval` 上计算的 t_R、t_Q、J。
- **置信区间**：
  - 单次运行的指标，用题面分组自助法：2000 次，seed 0（同 E1）；
  - 组间学会率的配对差，用 Newcombe 配对比例区间（方法 10）。

### 5.2 操纵检验（H-M）

- **A_lin(t)**：数字位置各记录点（不含 `emb`）上，P2 线性·标准化探针准确率的最大值。
  - 定义、代码和判定规则都与 E1 相同；
  - 探针在 `diag2_fit` 上拟合、在 `diag2_eval` 上评测，与训练用的辅助头无关。
- **门槛**：θ = c₀ + 0.5 · (A_lin(0) − c₀)，c₀ = 1/52。同一种子三个条件的初始化相同，所以 A_lin(0) 和 θ 也相同。
- **t_P2lin**：定义同 E1，在 E2-c 的检查点网格上计算。
- **操纵检验通过的条件**（分组计算，两条都要满足）：
  1. C1 中，至少 80% 的种子 t_P2lin 未发生；
  2. 配对符号检验：C1 在第 50–3000 步各检查点上 A_lin 的最小值，高于 C0 的种子数显著（精确符号检验，双侧 α = 0.05）。
- **前提复现检查**（不是操纵条件）：C0 中至少 80% 的种子 t_P2lin 发生，即在新种子上复现 E1 的现象。不满足时如实报告，结论中要说明前提没有复现。
- **特异性检查**（描述）：C2 是否也保持了可读性。如果是，C1 对 C2 的比较就不再只区分"绑定内容"，必须在解释中说明。
- **其他描述量**：
  - P2 的线性·原始特征探针和 MLP 探针（只在部分检查点运行，见 5.3）；
  - M3 敏感比例 s。

### 5.3 诊断（E2-c 精简版 D2c，沿用 E1 已验证的代码和定义）

- **检查点**（每次运行 14 个）：0、25、50、75、100、150、200、300、500、1000、2000、3000、6000、12000。它们都在 E1 的检查点网格之内。
- **每个检查点都做**：
  - M1：输出层面的指标，包括 P(根数字)、查询不敏感率、J、换查询双对率；
  - M2-P2：线性·标准化、线性·原始特征两种探针，包括打乱标签对照和同子集 `emb` 控制。
- **只在 0、75、150、3000、12000 这 5 个检查点做**：
  - M2-P2 的 MLP 探针；
  - M3 最小对敏感度，包括阴性、阳性对照；
  - M6 ACT 统计（只对 OpenMythos）。
- **只在 0 和 12000 做**：M0 实现检查。
- 不做 M4、M5 和 P1、P3。它们不是本实验的检验对象。
- 硬性检查（M0、M3 对照、探针对照）的规则与 E1 相同。

## 6. 复现与实现验证（实现阶段，需要单独授权；全部通过后才能冻结）

| 编号 | 内容 | 通过标准 |
|---|---|---|
| R1 | E2-c 训练脚本的 C0 路径与 E1 的 `train_k.py` 等价：非正式种子 99，两组各训练 200 步 | 权重逐位相同 |
| R1′ | 阴性对照"分离头"：C1 的辅助损失只作用于 `detach()` 后的状态，因此不回传到模型 | 与 C0 逐位相同。确认辅助机制本身不扰动训练 |
| R1″ | 参数层面范数记录（`autograd.grad`）不改变训练轨迹 | 开启和关闭记录时逐位相同 |
| R2 | 复现 E1 的正式轨迹：E1 种子 1–5、两组，用 C0 路径训练到第 3000 步 | 第 25–3000 步的每个检查点，都与 E1 已归档的 checkpoint 逐位相同（从 LFS 取回，双哈希核对） |
| R3 | 复现 E1 的诊断数值：D2c 在 E1 的 checkpoint 和 E1 的 `diag_fit` / `diag_eval` 上，与 E1 结果中 M1、M2-P2 的对应数值比较 | 完全相同（容差 1e-6，事先固定） |

| V3 | 计时：在非正式种子上测量 C0、C1、C2 的训练耗时和 D2c 的诊断耗时 | 记录实测值，代替第 8 节的估计 |
| V4 | 续跑启动器的故障注入测试：沿用 E1 的测试，并增加 C1 → C2 依赖、配对记录缺失或被改动、测试集承诺不符等情形 | 全部通过 |

- R2 不通过（例如运行环境的库版本变化导致不能逐位复现），就停止并报告。
  - 这时不能把 E1 运行当作历史队列的 C0；是否在新环境中重新训练，需要审核决定。

## 7. 统计分析与判定

### 7.1 OpenMythos：确认性主检验族

- **P1**：C1 对 C0，第 12000 步"学会"的比例。用配对精确 McNemar 检验，双侧。
- **P2**：C1 对 C2，同样的检验。
- **多重比较**：两个检验用 Holm 校正，族内 α = 0.05。
- **效应估计**：配对学会率差，附 Newcombe 95% 置信区间。
- **最小关注效应**：Δ_min = 0.30。

**判定表**（按以下顺序判定，第一条适用的即为结论）：

| 条件 | 结论 |
|---|---|
| 操纵检验（5.2）未通过 | **不可判定**：操纵失败，H 无法检验。结果照常报告 |
| C0 中未学会的种子少于 5 个 | **不可判定（无改善空间）**：学会率对比不提供信息。t_L 只作描述 |
| P1 显著且 C1 > C0，P2 显著且 C1 > C2 | **支持 H**：保持绑定的线性可读性提高了学会率，而且是绑定特异的效应 |
| P1 显著且 C1 > C0，P2 不显著 | **支持"辅助监督提高学习"**，但不能归因于绑定内容（A2）。C2 对 C0 的比较作为描述报告 |
| P1 不显著，且 Newcombe 区间上限 < Δ_min | **否定 H（在本设定下）**：保持线性可读，不足以使学会率提高 ≥ 0.30 |
| P1 不显著，且区间上限 ≥ Δ_min | **不确定**：本样本量下无法区分"无效"和"中等效应" |
| P1 显著且 C1 < C0 | **与 H 相反**：绑定辅助监督损害了学习 |

### 7.2 Transformer：确认性次检验族（单独成族，不影响 7.1 的结论）

- **学会率**：与 7.1 相同的 P1、P2 检验和判定。预计有天花板，按 7.1 的"无改善空间"规则处理。
- **学会速度**：关键次要检验。
  - 比较 C1 对 C0、C1 对 C2 的 t_L，用配对精确符号检验；
  - 每个种子按"更早 / 更晚 / 相同"计数，"未发生"视为晚于任何步数，相同不计入；
  - Holm 校正，族内 α = 0.05。
  - 报告配对差（按日志点的步数）的中位数，附种子自助法置信区间：10000 次，seed 0。

### 7.3 次要和描述性分析（只给名义 p 值，不作确认性结论）

- 两组的 t_R、t_Q、t_L 及其先后关系（按 E1 第 5.2 节的标签）；
- C2 对 C0 的比较；
- 第 12000 步的准确率、查询不敏感率、J；
- A_lin、MLP 可读性、M3 s 的轨迹；
- OpenMythos 的 ACT 统计；
- 参数层面的辅助梯度范数和裁剪比例；
- α_t 达到上限的比例。

### 7.4 新的正式留出测试集与封存

- **题面来源**：只从留出题面（sha256 键对 10 取余为 0）中抽取，所以训练中按构造不可能出现。
- **排除**：先排除 E1 的所有 K=2 题集用过的键（两种语句顺序都排除），包括：
  - `dev_heldout`、`test_heldout`（含换根、换查询反事实题面）、`diag_fit`、`diag_eval`；
  - `minpair` 中属于留出部分的题面。
- **E2-c 的新题集**（都与上述 E1 题集、彼此之间不重叠）：

| 名称 | 规模 | 用途 | RNG |
|---|---|---|---|
| `dev2_heldout` | 500 题面 × 2 查询 | 训练日志、t_L | 72000 |
| `diag2_fit` | 1000 题面 × 2 查询 | 只用于拟合探针 | 73000 |
| `diag2_eval` | 1000 题面 × 2 查询 | D2c 的所有指标 | 74000 |
| `minpair2` | 由 `diag2_eval` 派生，规则同 E1 修订 9.3 | M3 | 75000 |
| `test2_heldout` | 1000 题面 × 2 查询，附换根、换查询反事实题（规则同 E1） | 只在第 12000 步做一次正式判定 | 见下文封存方式 |

- **封存方式**（待审核决定 D5）：
  - **方案 S（推荐）：审核人盐值**。
    - 冻结之前，审核人提供一个盐值的 sha256，写入冻结文件；
    - 测试集 RNG 种子由盐值派生，盐值在正式判定授权时才公开；
    - 判定阶段先核对盐值与哈希一致，再生成测试集，核对隔离；
    - 因此在判定之前，执行方无法生成测试集。
  - **方案 R：固定 RNG + 哈希承诺**。
    - 冻结时用 RNG 76000 生成测试集，只保存其 sha256 和规模，然后删除文件；
    - 判定阶段重新生成，核对哈希；
    - 这一方案只能证明测试集没有被改动，不能防止提前生成，后者要靠流程审计。
- **使用规则**：
  - 只有正式判定脚本可以生成和读取 `test2_heldout`。代码中出现该名称的文件必须在冻结清单中列出，并由审计核对；
  - 每个运行只判定一次，判定文件只写一次；
  - 非正式运行和校准运行一律不在它上面评测。
- **隔离检查**：
  - E2-c 各题集之间、与 E1 各题集之间的题面重叠为 0；
  - 所有留出题集与全部种子的 12000 步训练流的重叠为 0。按构造必然为 0，仍要实际核对；
  - `test2_heldout` 的隔离检查在判定阶段生成之后进行。不为 0 时，停止，不判定。

## 8. 计算资源、预计耗时与预算

### 8.1 运行数量

| 部分 | 运行数 |
|---|---|
| OpenMythos 确认性 | 20 个种子 × 3 个条件 = 60 |
| Transformer 确认性 | 10 × 3 = 30 |
| 历史队列（C1、C2） | 5 × 2 个条件 × 2 组 = 20 |
| 历史队列 C0 | 不重新训练（E1 的运行，R2 复现），只用 D2c 重新诊断，共 10 个 |

### 8.2 预计耗时

估计依据：E1 实测值，4 个并行进程。冻结前用 V3 的实测值代替。

| 项目 | 单次估计 | 合计（进程·分钟） |
|---|---|---|
| 训练 OpenMythos C0 | 约 40 分钟（E1 实测 33–44） | 20 × 40 = 800 |
| 训练 OpenMythos C1 / C2 | 约 44 分钟（估计 +10%） | (40 + 10) × 44 = 2200 |
| 训练 Transformer C0 | 约 18 分钟（E1 实测 17–18.5） | 10 × 18 = 180 |
| 训练 Transformer C1 / C2 | 约 20 分钟 | (20 + 10) × 20 = 600 |
| D2c 诊断 OpenMythos | 约 40 分钟 / 运行 | 75 × 40 = 3000 |
| D2c 诊断 Transformer | 约 14 分钟 / 运行 | 45 × 14 = 630 |

- **D2c 单次耗时的来源**：按 E1 各模块的实测耗时推算：
  - M1：OpenMythos 35 s，Transformer 13 s；
  - P2 的两种线性探针：估计 40 s 和 15 s；
  - 5 个检查点上的 MLP 和 M3：估计 260 s 和 86 s。
- **合计**：
  - 训练约 3780 进程·分钟，即约 15.8 小时；
  - 诊断约 3630 进程·分钟，即约 15.1 小时；
  - 正式判定约 120 次评测，约 0.3 小时；
  - 归档推送与取回核验约 0.5 小时；
  - **总计约 31.7 小时**（墙钟时间）。
- **硬上限**（提议）：训练与诊断合计 40 小时，按多次启动累计，不因续跑重置（规则同 E1 第 12 节）。达到上限即停止，退出码 7。
- **超出上限时的削减顺序**：若 V3 实测的估计超过上限，按以下事先固定的顺序削减，直到不超过上限：
  1. 去掉历史队列的 C2；
  2. MLP 和 M3 只在 0、150、12000 三个检查点做；
  3. Transformer 确认性减为 8 个种子。
  - 不削减 OpenMythos 确认性的种子数、主要指标和操纵检验。
  - 仍然超出时，停止并提交审核。

### 8.3 存储

- **归档范围**：每次运行归档 13 个 checkpoint（14 个检查点中，第 0 步可以重建），每个约 2.45 MB，即每次运行约 32 MB。
- **总量**：110 次运行约 3.5 GB。加上 E1 已有的 0.64 GB，共约 4.2 GB，低于 10 GB 存储额度。
- **带宽**：
  - 按 E1 的规则，每次归档后都要在全新目录中取回核验，约 3.5 GB；
  - 运行结束后的全量复核，再需要约 3.5 GB；
  - 两者合计接近每月 10 GB 的带宽额度。
- **提议**（待审核决定 D6）：
  - 运行后的复核改为事先固定的 20% 随机样本，约 0.7 GB；
  - 启动前由所有者确认当月的剩余额度。

## 12. 潜在混杂、阴性对照与解释限制

### 12.1 潜在混杂与处理

| 混杂 | 处理 |
|---|---|
| 额外监督和额外梯度本身的作用 | C2：同样的头、位置、记录点和标签数，误差信号范数与 C1 逐步配对（3.2） |
| 辅助头增加的参数 | 头固定不训练，C1 与 C2 相同（D1） |
| 优化器状态（AdamW 二阶矩包含了辅助梯度，改变了有效学习率） | C1 与 C2 在误差信号范数上配对；参数层面的范数记录并报告 |
| 梯度裁剪（辅助梯度增大总范数，使任务梯度被缩小） | 记录三种条件的裁剪比例；C1、C2 配对 |
| C2 本身可能有害（噪声注入、把输出推向均匀分布），使 C1 对 C2 的差异被夸大 | 判定表要求 P1（C1 对 C0）必须显著；C2 对 C0 单独报告 |
| C2 可能也保持了可读性 | 特异性检查（5.2），在解释中说明 |
| 辅助监督改变了其他表示或 ACT 行为 | M1、M3、M6 描述 |
| λ 的选择偏向结果 | λ 只按可读性、只用非正式种子、按事先固定的规则选择（3.3） |
| 种子之间的差异 | 按种子配对；确认性种子事先指定，不挑选 |
| Transformer 的天花板 | 学会速度作为它的次检验（7.2） |
| 多重比较 | 每族用 Holm 校正；次要分析只给名义 p 值 |
| 运行环境变化导致不能逐位复现 | R2；不通过就停止（F2） |

### 12.2 阴性对照

- **C2**：信息内容的阴性对照。
- **R1′ 分离头**：辅助机制存在、但梯度不回传时，必须与 C0 逐位相同。
- **探针对照**：沿用 E1 的打乱标签对照、同子集 `emb` 控制、植入信号灵敏度。
- **M3 对照**：阴性对照（只交换查询，查询之前的位置不变）和阳性对照（沿用 E1）。
- **正式判定的基准**：50% 是与查询无关策略准确率的上界（同 E1 修订 10.2）。

### 12.3 解释限制

- E2-c 只检验充分性：保持线性可读是否改善学习。它不检验必要性。即使 C1 改善了学习，也不能说明 C0 的失败是由可读性下降造成的。
- C1 的效应即使存在，途径也可能不只是"可读性"。例如辅助任务可能促进了数字位置对本语句字母的注意力，也就是"绑定头"的形成。本设计不区分这些途径，结论表述为"绑定辅助监督"的效应。
- 线性可读由独立探针在诊断集上测量，并按 E1 的规则判定。它不等于模型实际使用了这些信息。
- 结论只适用于本任务（K=2）、这两个模型规模和这套训练配方，不外推到 K=4 或更大的模型。
- 两组分别报告，不判断架构优劣。
- OpenMythos 的确认性样本量（N = 20）只对强效应有足够功效（第 4 节）。"不确定"的结论不能解读为"无效"。

## 13. 完整性审计方案（沿用 E1 已验证的机制）

- **冻结**：冻结文件 `e2c_workload_freeze.json` 记录：
  - E2-c 代码树（`e2c/*.py`，以及被导入的 E1 模块和 `open_mythos/*.py`）的 sha256；
  - 本预注册定稿的 sha256；
  - 题集清单的 sha256、测试集封存承诺（盐值哈希或测试集哈希）；
  - λ（每组）、种子表、检查点网格、工作量和预算上限。
  - 每次启动都与冻结基线逐项核对（同 E1 12.8）。
- **续跑启动器**：
  - 账本：checkpoint 清单、结果、配对记录、判定、预算；
  - 原子写入；经核实才跳过；用隔离代替覆盖；
  - checkpoint 经 LFS 核实后恢复；判定只写一次。
- **配对记录**：C1 的 r_t 记录作为运行产物归档；其 sha256 写入 C1 的运行记录和 C2 的运行记录，判定前由审计核对。
- **checkpoint**：
  - 推送到私有仓库 `leotree2020/openmythos-artifacts`（新路径 `gate_e/e2c/`），在全新目录中取回，核对文件和参数两个哈希；
  - 研究分支不提交任何 `.pt` 文件。
- **同步**：运行记录持续同步到研究分支，不含 checkpoint。
- **运行后核验**（与 E1 的 `verify_formal_run.py` 相同结构）：
  - 冻结文件没有改动；
  - checkpoint 双哈希一致（按 D6 的抽样范围）；
  - 结果、判定与账本一致；
  - 配对记录哈希一致；
  - 事件表能重现；
  - 预算没有被重置；
  - 代码中读取 `test2_heldout` 的文件只限于判定脚本。
- **审计日志**：记录每个阶段的审核结论、验证、偏差和失败。失败记录一律保留，不覆盖。
