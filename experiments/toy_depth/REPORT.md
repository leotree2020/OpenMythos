# 递归深度消融报告（Claude 侧，tiny Shakespeare）

按《OpenMythos 递归深度消融：统一测试协议》执行。本报告只包含 Claude 侧的独立结果；与 Work 侧正式 checkpoint 的对齐判断，需等 Work 结果出来后再做。

## 1. 实验配置

| 项 | 值 |
|---|---|
| 模型 | OpenMythos 原版结构：GQA、MoE（4 个路由专家 + 1 个共享专家，每 token 激活 2 个）、prelude 1 层 + 循环块 + coda 1 层；dim 128，约 0.61M 参数 |
| 训练 | 固定 T=4；字节级（vocab 256）；tinyshakespeare 前 90%；2500 步，batch 32，seq 128；AdamW，lr 2e-3，warmup 加余弦退火；只用 next-token CE |
| 种子 | 1、2、3，checkpoint 的 sha256 见 `protocol_summary.md` |
| 测试集 | tinyshakespeare 后 10%（按段落边界切分），111,606 字节，token 流的 sha256 为 84fafd9c8f37… |
| 评测 | seq 128，batch 16，CPU fp32；源码 commit cb64586（工作区干净）；三个 checkpoint 均通过"开关全关 = 原版前向"的逐位等价性验证 |
| PPL 口径 | 分子：除 token 流第一个 token 外，所有 token 的 NLL 之和；分母：测试文本的 UTF-8 字节数；所有规则、所有 T 都相同。字节分词下 token PPL 与 byte PPL 只差这一个 token |
| 规则 / 深度 | BASE、B1、B2、C，T=4、8、16（核心评测）。B1+C 和 B2+C 按协议"按需执行"，未运行，理由见第 4 节 |

原始数据：`protocol.jsonl`；汇总表：`protocol_summary.md`。
补充数据：本轮协议之前已启动的扩展深度评测（T=1、2、3、4、6、8、12、16，规则对应关系为 base=BASE、remainder=B1、clamp=C、both=B1+C），见 `results.jsonl`，按协议未打断。

## 2. 观察到的现象

**2.1 没有深度退化。** 三个种子的 PPL 在 T=4、8、16 下相同，差异在 ±0.01% 以内：

| 种子 | BASE T=4 | BASE T=8 | BASE T=16 |
|---|---|---|---|
| 1 | 4.5986 | 4.5988 | 4.5988 |
| 2 | 4.6390 | 4.6389 | 4.6389 |
| 3 | 4.5815 | 4.5814 | 4.5814 |

扩展深度评测也一样：T=6、8、12、16 与 T=4 相同。T<4 时 PPL 明显变差，例如 T=1 的均值为 12.12。

**2.2 ACT 停机很早，多给的轮数基本没用上。** 区分协议要求的三种深度指标：

| 指标 | T=4 | T=8 | T=16 |
|---|---|---|---|
| ACT 有效停机深度（各 token 首次停机轮次的均值，三个种子） | 2.30 / 2.15 / 2.61 | 2.31 / 2.15 / 2.66 | 同 T=8 |
| 每次前向调用实际执行的循环数 | 4.00 | 5.06 | 5.06 |
| 循环计算量（执行轮数 × token 数，相对同规则 T=4） | 1.00× | 1.27× | 1.27× |

- 停机轮次分布：大部分 token 在第 2 轮停机（种子一 76%、种子二 82%、种子三 56%），几乎全部在第 5 轮之前停机。
- 三种指标明显不同：token 平均约 2.3 轮就停机，但前向调用在 T=4 时每次都跑满 4 轮。原因是提前退出要等整个 batch 都停机，最慢的那个 token 决定了计算成本。
- T≥8 时，前向调用平均在约 5 轮处结束，因为到那时 batch 内所有 token 都已停机。

**2.3 ACT 输出权重和几乎都是 1。** T=4 时，未达到停机阈值的位置比例为 0.3% / 0.1% / 2.0%，平均权重和为 1.000 / 1.000 / 0.998。T≥8 时，所有位置都达到阈值。

**2.4 隐藏状态没有外推异常。** 每轮隐藏状态的 RMS 稳定在 1.4–1.8 之间，没有增长。每轮的相对变化量单调减小，例如种子一：1.29 → 0.35 → 0.21 → 0.17 → 0.13 → 0.11。超过训练深度的第 5、6 轮没有出现跳变；状态在缓慢收敛，但还没收敛到不动点。

**2.5 时间成本。** T=8 和 T=16 的墙钟时间是 T=4 的 1.11–1.27 倍，与循环计算量的 1.27 倍基本一致。时间是单次 CPU 测量，噪声较大，以循环计算量为准。

## 3. 有效的干预

**在本模型上，没有任何规则产生了可测量的改善。** 下表为 L1，各规则与同 T 下的 BASE 相比的 PPL 变化，取种子均值：

| 规则 | T=4 | T=8 | T=16 |
|---|---|---|---|
| B1 | −0.00% | +0.00% | +0.00% |
| B2 | −0.00% | +0.00% | +0.00% |
| C | +0.00% | +0.00% | +0.00% |

（单个种子的最大差异是 +0.01%。）

- **L2**（各规则自身 T=8、T=16 与 T=4 相比）：变化全部在 ±0.01% 以内。没有任何规则的 T=4 比 BASE 的 T=4 更差，因此不存在"T=4 变差、所以 4→8 差距缩小"的假改善。
- **L3**（计算是否划算）：T≥8 多花约 27% 的循环计算，PPL 收益为 0。**增加计算不划算。**
- 补充：B1 在 **T 小于训练深度** 时大幅降低 PPL（T=1：12.12 → 5.13；T=2：5.80 → 4.66）。这是低于训练深度时的读出补偿，**不属于深度外推的改善**，不应作为 B1 的支持证据。

## 4. 尚未证明的因果解释

以下是根据数据得出的推断，还没有经过干预实验验证：

1. **规则没有效果，是因为它们没有作用对象。** B1 和 B2 只影响未达阈值的位置，而 T=4 时这类位置只占 0.1–2%。C 只影响第 5 轮及之后，而到那时所有位置的 ACT 输出权重都已是 0（C 确实改变了第 5、6 轮的隐藏状态，相对变化量从 0.132 降到 0.127，但这些状态不进入输出）。这能解释"零效果"，但不能说明这些规则对正式模型无效。
2. **ACT 在训练中学会了"早停"**，平均停机深度约为训练深度的一半。所以 T=4 时已经有一半左右的轮次权重为 0，额外的深度在结构上用不上。这是现象层面的描述；为什么会学成这样（例如没有 ponder cost、阈值设定、模型容量）尚未验证。
3. **小模型和正式模型的差异**，最可能出在 ACT 行为上：正式模型在 T=4→8 出现退化（+0.4% 到 +50%），说明它在 T=4 时可能有相当多的位置没停机，或者超过训练深度的轮次仍有非零权重。这一点需要 Work 侧的诊断指标来确认，Claude 侧无法推断。
4. 因为没能复现退化，**本实验无法检验 B1、B2、C 对正式模型的退化是否有效**。为此组合消融 B1+C、B2+C 也没有执行价值，按协议未运行。

## 5. 是否需要重新训练

- 就"消除深度退化"而言，本模型不需要，因为它没有退化。
- 就本轮目标"稳定地利用额外计算"而言，**仅靠推理时的规则是不够的**。本模型额外的轮数稳定，但没有用处：ACT 读出让已停机位置后续轮次的权重为 0。要让额外计算产生收益，必须改变训练方式，例如随机深度训练，或者用最后一轮状态作为读出。
- 相应的对比实验（固定深度 / 随机深度 × ACT 读出 / 最后一轮读出，各 3 个种子，多跳变量追踪任务）正在 `experiments/loop_mech/` 中运行，尚未得出结果。

## 6. 是否值得扩大模型规模

**不值得。** 在本配置下，增加推理深度既不退化，也没有收益；而正式模型存在退化。两边都没有证据表明，扩大当前这套循环机制能更好地利用额外计算。应先在小规模上找到"T 增大 → 性能提升"的机制，再考虑扩大规模。这与 Work 侧"暂不扩大这套配置"的判断一致。

## 7. 需要 Work 侧提供以对齐

协议第 5 节要求比较的是"相同方向"，而不是绝对值。Claude 侧需要 Work 侧的以下几项：

- 正式模型 BASE 在 T=4 下的：停机轮次分布、未达阈值比例、平均权重和。这是判断"两边 ACT 行为是否相似"的关键。
- T=8、T=16 下，每次前向实际执行的循环数，以及第 5 轮及之后的隐藏状态 RMS 和变化量（是否发散）。
- B1、B2、C 在正式模型上的 L1 和 L2 结果。

Work 可以直接用 `training/depth_protocol_eval.py`（GPU、HF 分词器，参数 `--seq-len`、`--batch-size` 应与原评测一致），用 `training/depth_protocol_summary.py` 生成同格式的表。
