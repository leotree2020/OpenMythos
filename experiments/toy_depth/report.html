OpenMythos 递归深度诊断

在小型 OpenMythos（tiny Shakespeare）上，按统一测试协议检验 BASE、B1、B2、C 四种规则在 T=4、8、16 下的表现，并据此给出寻找改善办法的路线。本页供 Work 对齐使用，绝对 PPL 不与正式模型直接比较。

Claude 侧协议评测已完成 Work 侧正式模型等待诊断数据 训练机制对比进行中，无结果
结论实验设置观察到的现象干预效果可检验的推论未证明的解释改善路线需要 Work 提供更正与说明复现信息

§0结论

现象
小模型没有深度退化
三个种子在 T=4、8、16 下 PPL 相同，差异在 ±0.01% 以内。
现象
多给的轮数没被使用
token 平均在第 2.15–2.66 轮首次停机；T≥8 多花 27% 循环计算，收益为 0。
干预
B1、B2、C 都没有可测效果
它们的作用对象（T=4 时未停机的 0.1–2% 位置、第 5 轮之后的状态）在这个模型上几乎不存在。
推论
正式模型的退化只能来自 T=4 时未停机的位置
这是代码层面的必然结论，可以用 Work 的诊断数据直接检验。

对改善方向的含义：推理时的规则最多能做到"多给的轮数不帮倒忙"，做不到"让多给的轮数有用"。本轮目标是找到能稳定利用额外计算的循环机制，这需要改变训练方式。推理侧规则的价值在于诊断，以及在正式模型上止损。详见 §6 改善路线。

§1实验设置

模型OpenMythos 原版结构：GQA 注意力；MoE（4 个路由专家 + 1 个共享专家，每 token 激活 2 个）；prelude 1 层 + 循环块 + coda 1 层；dim 128；约 0.61M 参数
训练固定 T=4；字节级分词（vocab 256）；tinyshakespeare 前 90%；2500 步，batch 32，seq 128；AdamW，lr 2e-3；warmup 加余弦退火；只用 next-token CE，没有 ponder cost
种子1、2、3（与正式实验相同的三种子设计）
测试集tinyshakespeare 后 10%（按段落边界切分），111,606 字节
评测seq 128，batch 16，CPU fp32；评测时没有其他训练进程争用 CPU
PPL 口径分子：除 token 流第一个 token 外，所有 token 的 NLL 之和；分母：测试文本的 UTF-8 字节数。所有规则、所有 T 都相同。字节分词下 token PPL 与 byte PPL 只差这一个 token
规则BASE（原版）；B1 最后一轮补齐剩余权重；B2 按实际 ACT 权重和归一化；C 超过训练深度后截断轮次编码。B1+C、B2+C 按协议"按需执行"，因独立消融均无效果而未运行
等价性三个 checkpoint 均验证：所有开关关闭时，外部适配层的前向与原版逐位相同（torch.equal）

§2观察到的现象

2.1 PPL 随推理深度的变化

字节级 PPL 与推理深度 T（训练深度 T=4，纵轴为对数刻度）
实线为 BASE，虚线为 B1。T≥4 时所有曲线重合并保持平坦；B1 只在 T 低于训练深度时有作用。
来源：experiments/toy_depth/results.jsonl（扩展深度评测，base=BASE，remainder=B1）

2.2 ACT 停机分布

各 token 首次达到停机阈值的轮次（BASE，T=8）
大部分 token 在第 2 轮就停机，几乎全部在训练深度 T=4 之前或刚超过时停机。
来源：experiments/toy_depth/protocol.jsonl，字段 act_halt_hist

2.3 三种深度与计算量指标

协议要求区分这三者。下面是三个种子的值；它们差别很大，所以不能互相替代。

差距的来源：提前退出要等整个 batch里所有位置都停机。token 平均约 2.3 轮就停，但 T=4 时每次前向都跑满 4 轮，因为每个 batch 里总有少数位置没停。T≥8 时，前向调用在约 5 轮处结束。所以实际计算成本由每个 batch 里最慢的位置决定，而不是由平均停机深度决定。

2.4 ACT 输出权重和

T=4 时，未达到停机阈值的位置占 0.1%–2.0%，平均权重和是 0.998–1.000。T≥8 时，所有位置都达到了阈值。按协议，权重和小于 1 不预设为必须修复的错误；在这个模型上，它涉及的位置太少，修与不修都没有影响。

2.5 隐藏状态是否在超出训练深度后出现异常

每轮隐藏状态的相对变化量 ‖ht − ht−1‖ / ‖ht−1‖（强制跑满 16 轮，不提前退出）
三个种子都单调下降，越过训练深度（虚线）时没有跳变。状态在缓慢收敛，到第 16 轮仍有约 4–7% 的变化，还没收敛到不动点。
来源：experiments/toy_depth/act_stats.json（钩子观测，停机阈值临时设为无穷大）

每轮隐藏状态的 RMS 保持在 1.4–1.8 之间，没有增长（详见 protocol_summary.md 的诊断表）。C 确实改变了第 5、6 轮的隐藏状态（例如种子一第 6 轮的相对变化量从 0.106 降到 0.100），但这些轮次的 ACT 输出权重都是 0，所以不影响输出。

§3干预效果

按协议的三层判断方法。数值为相对变化，取种子均值；单个种子的数值见 protocol_summary.md。

第一层：与同 T 下的 BASE 相比

第二层：同一规则，更深的 T 与 T=4 相比

没有任何规则的 T=4 比 BASE 的 T=4 更差，所以不存在"T=4 变差、导致 4→8 差距缩小"的假改善。

第三层：增加的计算是否划算

墙钟时间是单次 CPU 测量，有噪声；以循环计算量（执行轮数 × token 数）为准。

B1 在低于训练深度时的作用，不算深度外推的改善
B1 让 T=1 的 PPL 从 12.12 降到 5.13，T=2 从 5.80 降到 4.66。这是 T 小于训练深度时的读出补偿，与"超出训练深度后能否利用额外计算"无关。

§4一个可以检验的推论

原版循环块里，一个位置停机后，在后续轮次的输出权重为 0；同一个 batch 里的不同序列也不会互相做注意力。因此在不使用 KV cache 的评测中：

如果 T=4 时某个序列的所有位置都已停机，这个序列在任何 T≥4 下的输出都与 T=4 逐位相同。
已有单元测试固定了这一点（test_all_halted_output_is_depth_invariant）。

由此可以推出三件事：

  1. 正式模型 T=4→8 的退化，只能从 T=4 时未停机的位置开始。已停机的位置只能通过 coda 层对这些位置的注意力被间接影响。
  2. 可以检验的预测：三个种子的退化幅度（+7.2%、+0.4%、+50.0%）应该与 T=4 时未停机位置的比例或权重质量正相关，种子三应该最高。如果不是这样，就说明有别的机制（例如数值精度、评测时用了 KV cache），需要重新排查。
  3. batch 大小不影响 PPL，只影响计算成本。这一条更正了此前的说法，见 §8。

为了直接检验，新增了归因工具 training/depth_attribution.py：它逐 token 计算 T=4→T 的 NLL 变化，并按 T=4 时的 ACT 状态拆分，具体是"已停机"和"未停机"两组；未停机的再按权重和分档，以及按在更深的 T 下第几轮停机分档。

§5尚未证明的因果解释

  • 规则无效是因为没有作用对象。B1、B2 只影响 T=4 时未停机的位置（0.1–2%）；C 只影响第 5 轮之后，而那时所有位置的权重都已是 0。这能解释小模型上的"零效果"，但不能推出这些规则在正式模型上也无效。
  • ACT 在训练中学会了"早停"。平均停机深度约为训练深度的一半，T=4 时已有约一半的轮次权重为 0。可能的原因包括：没有 ponder cost 约束、停机阈值的设定、模型容量小、任务太容易。目前都没有验证。
  • 小模型和正式模型的差异可能出在 ACT 行为上。正式模型 T=4 时很可能有相当多的位置没停机。在 Work 的诊断数据出来之前，这只是推测。
  • "多给的轮数没有用"是否因为任务本身不需要更深的计算。字符级 Shakespeare 可能主要依赖局部模式。为此另开了多跳变量追踪实验，那个任务的深度不够就一定做不对，见 §6 阶段 2。

§6改善路线

目标不是修出一个 PPL 好看的版本，而是找到能稳定利用额外思考计算的循环机制。"成功"按以下三条判断：

标准含义本模型现状
不过度思考T 超过训练深度后，所有种子的 PPL 都不升高满足（但原因是额外轮数没被使用）
真的有收益在需要多步计算的任务上，T 越大越好，并能处理比训练时更难的样本不满足：T≥8 收益为 0
稳定多循环时隐藏状态收敛而不是发散，三个种子的结论一致满足：变化量单调下降，三种子一致
阶段 0
诊断

在正式模型上定位退化来源（Work，不需要训练）

用 depth_protocol_eval.py 和 depth_attribution.py 跑三个正式 checkpoint。根据结果，按下表决定下一步：

如果诊断结果显示说明下一步
T=4 未停机比例高，且 ΔNLL 主要来自这些位置退化来自"未停机位置在第 5 轮之后得到的权重"在正式模型上比较 B1、B2；同时检查这些位置在第 5–8 轮的隐藏状态
第 5 轮之后隐藏状态 RMS 增大或变化量反弹循环本身在训练深度之外不稳定比较 C；考虑状态归一化或收缩约束（需要训练）
退化幅度与未停机比例不相关§4 的推论不成立，存在别的机制先排查评测是否用了 KV cache、数值精度、batch 内的提前退出逻辑
B1、B2、C 都救不回来推理侧补丁无法解决直接进入阶段 2
阶段 1
止损

推理侧安全默认值（不重训）

在找到有效机制之前，正式模型推理时把实际深度限制为 min(T, 训练深度)。这保证不会退化，但也不会有收益，只是一条基线。B1、B2、C 只有在阶段 0 证明对正式模型有效后才采用；采用时必须同时报告它们对 T=4 本身的影响。

阶段 2
机制

改变训练方式，让额外的轮数有用

这是本轮目标的核心。推理侧规则做不到，因为 ACT 读出会让已停机位置在后续轮次的权重为 0。候选方向如下（引用是凭记忆给出，细节需要核对原文）：

A. 训练时随机采样循环深度对比实验进行中

每一步随机选 T，让模型学会在任意深度下都可用，而不是只在 T=4 可用。Geiping 等人（2025）的循环深度模型采用了这一思路，并只对最后几轮反向传播以控制成本。

检验：PPL 随 T 的曲线在超出训练平均深度后是否继续下降；三个种子是否一致。
B. 用最后一轮状态做读出，ACT 只负责提前退出对比实验进行中

取消各轮加权和，输出直接取最后一轮的状态；ACT 只决定"可以提前退出"，不参与输出。这样每多跑一轮都会影响输出，额外计算在结构上不再被屏蔽。

检验：与 A 组合（2×2 设计）；额外轮数是否带来收益，状态是否收敛。
C. 给停机加约束（ponder cost 或停机正则）待设计

原版训练只用 CE，没有约束停机行为。本模型平均在第 2.3 轮就停机，可能是无约束训练的结果。加入 ponder cost（Graves, 2016）或对停机深度的正则，可以研究"停机深度是否随样本难度变化"。

检验：停机深度分布与样本难度的相关性；正式模型的未停机比例是否下降。
D. 渐进式训练与重新注入输入待设计

Bansal 等人（2022）用"从中间状态继续算，并在每一轮重新注入原始输入"的训练方式，专门解决"算得越久越差"的过度思考问题。OpenMythos 的 LTI 注入已在每轮注入输入，缺的是渐进式训练这一部分。

检验：在多跳任务上，测试跳数超过训练跳数时，增加 T 能否提高准确率。

A×B 的 2×2 对比正在 experiments/loop_mech/ 中运行：多跳变量追踪任务，训练 1–4 跳、测试 1–12 跳，序列长度固定，每种机制 3 个种子。目前每个机制的种子一大约训练到 600/3000 步，尚无结果。

阶段 3
扩大

扩大规模的门槛

现在不值得扩大。两边都还没有证据表明这套循环机制能利用额外计算。建议的门槛是：某个机制在小规模上同时满足上表的三条标准，并在三个种子上一致，然后再在正式规模上验证一个种子，最后才考虑扩大。

§7需要 Work 提供

协议要求比较方向，不比较绝对值。以下几项决定两边结果能否对齐，以及阶段 0 的走向：

  • BASE 在 T=4 下的停机轮次分布、未达阈值的比例、平均权重和（三个种子分别给出）
  • T=8、T=16 下每次前向实际执行的循环数，以及第 5 轮之后隐藏状态的 RMS 和变化量
  • 归因结果：T=4→8 和 T=4→16 的 ΔNLL 中，有多少来自 T=4 时未停机的位置
  • B1、B2、C 的第一层和第二层结果
  • 评测是否使用了 KV cache；seq-len 和 batch size 与原评测是否一致

命令示例（GPU、HF 分词器；--seq-len 和 --batch-size 请与原评测一致）：

git checkout claude/openmythos-research
export PYTHONPATH=training:.
python training/depth_protocol_eval.py --ckpt s1.pt s2.pt s3.pt \
  --data test.jsonl --rules BASE,B1,B2,C --n-loops 4,8,16 \
  --seq-len <原值> --batch-size <原值> --out protocol.jsonl
python training/depth_protocol_summary.py protocol.jsonl > protocol_summary.md
python training/depth_attribution.py --ckpt s1.pt s2.pt s3.pt \
  --data test.jsonl --ref-t 4 --n-loops 8,16 \
  --seq-len <原值> --batch-size <原值> --out attribution.jsonl

每个 checkpoint 正式评测前，脚本会先核对"开关全关 = 原版前向"，不一致就直接报错。结果文件的 meta 行记录了模型配置、源码 commit、checkpoint 的 sha256 和数据集指纹。

§8更正与说明

  • 更正：此前我说过"batch 大小会略微影响 PPL"，这是错的。batch 级提前退出只影响每次前向执行的轮数，即计算成本，不改变任何位置的输出（理由见 §4）。
  • B2 是新补充的规则，由外部适配层实现，与 B1 互斥。原版源码和原始 checkpoint 均未修改。
  • 本轮协议之前已启动的扩展深度评测（T=1、2、3、4、6、8、12、16）按协议没有打断，结果作为补充数据；名称对应关系：base=BASE，remainder=B1，clamp=C，both=B1+C。
  • 运行过程中的两次操作失误，都已处理、不影响结果：暂停训练进程时，误把执行命令的 shell 也暂停了，已恢复；误判排队任务的状态，导致协议评测同时启动了两份并写入同一个文件，两份都已丢弃，本页数据来自之后单独重跑的一份。
  • 墙钟时间是单次 CPU 测量，只作参考；计算成本以循环计算量为准。
